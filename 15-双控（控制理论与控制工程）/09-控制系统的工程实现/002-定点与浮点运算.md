# 定点与浮点运算

> **一句话直觉**：浮点数是"用精度换范围"，定点数是"用范围换速度"——在资源受限的MCU上，你需要学会用手中的位数画出一个足够用的数轴。

---

## 为什么控制算法会关心数值格式

想象你在做一个电机电流环控制，采样周期50 us，MCU是STM32F103（Cortex-M3，无FPU）。你的PI控制器里有这样的运算：

```c
float error = setpoint - adc_value;
integral += error * Ts;
output = Kp * error + Ki * integral;
```

如果没有FPU，`float` 乘法在72 MHz主频下需要约50-100个时钟周期（通过软件浮点库），而整个50 us周期里你只能执行约3600个周期。一次PID计算吃掉100周期，加上ADC读取、通信、其他任务，CPU利用率很快逼近极限。

如果把所有运算改成16位定点整数，一次乘加（MAC）只需要1个周期（用Cortex-M4的`SMMLA`）或几个周期（用C编译器优化）。这就是**定点运算的核心吸引力**。

但代价是什么？你需要手动管理小数点的位置，确保中间结果不会溢出，也不会因为分辨率太低而丢失有效信息。

## 定点数基础：Q格式

### 什么是Q格式

Q格式把一个 $N$ 位整数解释为带有固定小数位的有符号数。记为 $Q_m.n$，其中 $m$ 是整数位数，$n$ 是小数位数，$m + n = N - 1$（留1位给符号）。

```
Q15格式（16位）:
  位15: 符号位
  位14~0: 15位小数
  
  数值 = 整数值 / 2^15
  范围: [-1, 1 - 2^-15] ≈ [-1, 0.99997]
  分辨率: 2^-15 ≈ 3.05e-5
```

```
Q12格式（16位）:
  位15: 符号位
  位14~12: 3位整数（-4 ~ +3）
  位11~0: 12位小数
  
  范围: [-4, 4 - 2^-12]
  分辨率: 2^-12 ≈ 2.44e-4
```

```
Q0格式 = 普通有符号整数
```

### 快速对照表

| 格式 | 总位数 | 整数位 | 小数位 | 范围 | 分辨率 |
|------|--------|--------|--------|------|--------|
| Q15 | 16 | 0 | 15 | $[-1, 1)$ | $3.05 \times 10^{-5}$ |
| Q14 | 16 | 1 | 14 | $[-2, 2)$ | $6.10 \times 10^{-5}$ |
| Q12 | 16 | 3 | 12 | $[-4, 4)$ | $2.44 \times 10^{-4}$ |
| Q8 | 16 | 7 | 8 | $[-128, 128)$ | $3.91 \times 10^{-3}$ |
| Q31 | 32 | 0 | 31 | $[-1, 1)$ | $4.66 \times 10^{-10}$ |
| Q24 | 32 | 7 | 24 | $[-128, 128)$ | $5.96 \times 10^{-8}$ |

## 定点运算的四则运算规则

### 加法 / 减法

两个同格式Q数相加，结果格式不变。但可能溢出！

$$ Q_n(a) + Q_n(b) = Q_n(a+b) $$

**关键**：和的范围是加数范围的两倍。两个Q15数相加，结果可能需要Q14才能安全存放。

```c
// Q15 addition with saturation
int16_t q15_add(int16_t a, int16_t b) {
    int32_t temp = (int32_t)a + (int32_t)b;  // promote to 32-bit first!
    if (temp > INT16_MAX) temp = INT16_MAX;
    if (temp < INT16_MIN) temp = INT16_MIN;
    return (int16_t)temp;
}
```

### 乘法

两个 $Q_n$ 数相乘，结果暂时是 $Q_{2n}$（小数位翻倍），需要右移 $n$ 位回到 $Q_n$。

$$ Q_n(a) \times Q_n(b) = \frac{a}{2^n} \cdot \frac{b}{2^n} = \frac{a \cdot b}{2^{2n}} \xrightarrow{\text{>> n}} Q_n\left(\frac{a \cdot b}{2^n}\right) $$

```c
// Q15 multiplication: result is Q15
int16_t q15_mul(int16_t a, int16_t b) {
    int32_t temp = (int32_t)a * (int32_t)b;  // a*b is Q30, stored in 32 bits
    temp >>= 15;                              // back to Q15
    return (int16_t)temp;
}
```

**注意**：右移15位时，必须先把乘积放到32位变量里，不能在16位里右移（会丢失高16位）。

### 不同Q格式的混合运算

实际工程中，ADC读数可能是Q12，系数是Q15，输出要送给10位DAC。这需要格式转换：

```
ADC:  12-bit raw → Q12 (如果参考电压映射到±1)
Coeff: Q15
Product: Q12 * Q15 = Q27 (in 32 bits)
To output Q10 for DAC: >> 17  (27-10=17)
```

```c
int16_t adc_q12 = read_adc();           // Q12
int16_t coeff_q15 = float_to_q15(0.5f); // Q15

int32_t prod = (int32_t)adc_q12 * coeff_q15;  // Q27 in 32 bits
int16_t dac_out = (int16_t)(prod >> 17);      // Q10 for DAC
```

## 控制算法中的定点实现策略

### 策略1：统一Q格式法

把所有信号和系数都统一到同一种Q格式（比如Q15）。优点是简单，缺点是动态范围受限——如果电机电流既要在mA级微调，又要在过流时读到几十A，Q15根本不够。

### 策略2：缩放因子法（推荐）

给每个物理量分配一个"工程单位到Q格式"的缩放因子，在算法边界处做转换。

```c
// scaling factors (engineering units per LSB)
#define ADC_SCALE_VOLTS  (3.3f / 4096.0f)   // 12-bit ADC, 3.3V ref
#define DAC_SCALE_VOLTS  (3.3f / 1024.0f)   // 10-bit DAC

// internal signals are normalized to Q15 (±1.0 = ±full scale)
// For current: full_scale = 50A → 1.0 Q15 = 50A
#define CURRENT_FULLSCALE 50.0f

int16_t adc_to_q15_current(uint16_t adc_raw) {
    float voltage = adc_raw * ADC_SCALE_VOLTS;
    float current = (voltage - 1.65f) / 0.066f;  // hall sensor: 1.65V offset, 66mV/A
    return (int16_t)(current / CURRENT_FULLSCALE * 32768.0f);
}

uint16_t q15_to_dac_voltage(int16_t q15_val) {
    float voltage = (float)q15_val / 32768.0f * 3.3f;  // Q15 to volts
    uint16_t dac_code = (uint16_t)(voltage / DAC_SCALE_VOLTS);
    if (dac_code > 1023) dac_code = 1023;
    return dac_code;
}
```

### 策略3：块浮点法（高级）

对高阶滤波器或FFT，每个数据块共享一个指数缩放因子，而不是每个数单独缩放。这平衡了定点速度和浮点动态范围。Cortex-M4的CMSIS-DSP库就大量使用了这种技术。

## 数值示例：一个PI控制器的定点实现

**任务**：用16位定点实现一个PI电流控制器。

**参数**：
- $K_p = 0.5, K_i = 100$ （这个 $K_i$ 很大是因为 $T_s$ 很小，单位是 A/s per A error）
- $T_s = 50$ us
- 电流满量程：50A → 映射到Q15的±1.0
- ADC：12位，单端3.3V
- DAC：10位

**步骤1：确定缩放和Q格式**

信号选择Q15（±1.0对应±50A）。

$K_p = 0.5$ 可以用Q15直接表示：$N_{Kp} = 0.5 \times 32768 = 16384$。

$K_i = 100$ 远超Q15范围。解决方案：把积分增益拆成 $K_i = K_{i,scaled} \times scale$。

注意 $K_i$ 的单位是控制器输出（电压占空比或电压指令）每安培误差每秒。如果我们把输出也归一化到Q15（对应±100%占空比），那么：

$K_i \cdot T_s = 100 \times 50\times10^{-6} = 0.005$ 每个周期。

这个值可以用Q15表示：$N_{KiTs} = 0.005 \times 32768 = 163.84 \approx 164$。

**步骤2：写出定点PI代码**

```c
typedef struct {
    int16_t Kp;         // Q15
    int16_t KiTs;       // Q15: Ki * Ts
    int16_t integral;   // Q15
    int16_t y_prev;     // Q15
} FixedPI_Q15;

void fixedpi_init(FixedPI_Q15* c, float Kp, float Ki, float Ts) {
    c->Kp = (int16_t)(Kp * 32768.0f);
    c->KiTs = (int16_t)(Ki * Ts * 32768.0f);
    c->integral = 0;
    c->y_prev = 0;
}

// Q15 multiply: (a * b) >> 15
static inline int16_t q15_mul(int16_t a, int16_t b) {
    return (int16_t)(((int32_t)a * b) >> 15);
}

// Q15 addition with saturation
static inline int16_t q15_add_sat(int16_t a, int16_t b) {
    int32_t s = (int32_t)a + (int32_t)b;
    if (s > 32767) s = 32767;
    if (s < -32768) s = -32768;
    return (int16_t)s;
}

int16_t fixedpi_update(FixedPI_Q15* c, int16_t r_q15, int16_t y_q15) {
    int16_t e = q15_add_sat(r_q15, -y_q15);   // error in Q15
    
    // integral: integral += KiTs * e
    int16_t inc = q15_mul(c->KiTs, e);
    c->integral = q15_add_sat(c->integral, inc);
    
    // anti-windup: clamp integral
    if (c->integral > 29491) c->integral = 29491;  // 0.9 * 32768
    if (c->integral < -29491) c->integral = -29491;
    
    // P term
    int16_t P = q15_mul(c->Kp, e);
    
    // I term
    int16_t I = c->integral;
    
    // sum with saturation
    int16_t u = q15_add_sat(P, I);
    
    return u;  // Q15: ±1.0 = ±100% duty
}
```

**步骤3：验证数值**

假设稳态误差 $e = 0.01$（对应Q15值 $0.01 \times 32768 = 328$）：

- P = q15_mul(16384, 328) = (16384 × 328) >> 15 = 5373952 >> 15 ≈ 164
  - 实际值：164 / 32768 = 0.005 → 对应 $K_p \cdot e = 0.5 \times 0.01 = 0.005$ ✓

- inc = q15_mul(164, 328) = (164 × 328) >> 15 = 53792 >> 15 ≈ 1
  - 每周期积分增加1/32768 ≈ 3.05e-5
  - 对应 $K_i T_s \cdot e = 0.005 \times 0.01 = 5 \times 10^{-5}$ ✓

精度足够用于电流环。但如果 $e$ 更小（比如0.001），inc = q15_mul(164, 33) = (164×33)>>15 = 5412>>15 ≈ 0，完全丢失了！这就是**量化死区**。

## 浮点运算的工程考量

### 什么时候必须用浮点

| 场景 | 建议 |
|------|------|
| 算法涉及矩阵求逆或特征值 | 浮点（通常double） |
| 自适应控制（在线更新参数） | 浮点，参数收敛精度要求高 |
| 模型预测控制（MPC） | 浮点，QP求解器需要 |
| 低频温度/压力控制（Ts > 100ms） | 浮点，CPU有余量 |
| 高频电流/速度环（Ts < 100us） | 定点或无FPU的MCU用定点 |
| 成本敏感的批量产品 | 定点，省芯片钱 |

### IEEE 754浮点的隐藏陷阱

```c
float a = 0.1f;
float b = 0.2f;
if (a + b == 0.3f) {
    // This will NOT execute on most platforms!
}
```

因为 $0.1$ 在二进制浮点中是无限循环小数，存储的是近似值。$0.1 + 0.2 \approx 0.30000001$。

**控制器中的陷阱**：假设你用一个浮点变量做周期计数：

```c
float t = 0.0f;
while(1) {
    t += 0.001f;  // accumulate 1ms
    if (t >= 1.0f) {  // expect this after 1000 iterations
        // actually might execute at t=0.99999994 or t=1.0000001
    }
}
```

经过1000次累加，误差累积可达约 $10^{-4}$。在控制循环里，**永远用整数计数器代替浮点时间**。

## 常见错误与纠正

### 错误1：定点乘法后忘记右移，导致数值完全错误

**错误代码**：

```c
int16_t a = 16384;  // Q15: 0.5
int16_t b = 16384;  // Q15: 0.5
int16_t c = (a * b);  // WRONG! 16384*16384 = 268435456, truncated to 16-bit = 0
```

**后果**：$c$ 的16位结果是0，而不是期望的0.25（Q15: 8192）。

**纠正**：

```c
int32_t temp = (int32_t)a * (int32_t)b;  // 32-bit intermediate
temp >>= 15;                              // scale back to Q15
int16_t c = (int16_t)temp;               // c = 8192 = Q15(0.25)
```

### 错误2：在定点PI中，积分器用和信号相同的Q格式，导致低频分辨率不足

**错误代码**：

```c
int16_t integral_q15 = 0;  // same format as signals
// ...
integral_q15 += q15_mul(KiTs_q15, e_q15);
```

当误差很小时（比如稳态附近，e只有几个LSB），`q15_mul` 的结果可能是0，积分器完全停止更新。系统在稳态附近形成一个**死区**，出现稳态误差或极限环。

**纠正**：把积分器提升到更高精度格式（比如Q31或32位整数）：

```c
int32_t integral_q31 = 0;  // 32-bit accumulator, maybe Q30 or Q31

// update with higher precision
integral_q31 += (int32_t)KiTs_q15 * (int32_t)e_q15;  // Q30 result

// when using, shift down
int16_t I_q15 = (int16_t)(integral_q31 >> 16);  // adjust shift based on chosen format
```

很多工业伺服驱动器的电流环里，积分器都是32位或48位，而输出和比例通路保持16位。

## 自测习题

### 习题1

将 $-0.75$ 分别表示为Q15和Q12格式的整数值，并写出它们的16位二进制表示。

**答案**：

Q15: $N = -0.75 \times 32768 = -24576$

二进制：$24576 = 0b0110000000000000$，负数补码：$0b1001100000000000$

Q12: $N = -0.75 \times 4096 = -3072$

二进制：$3072 = 0b0000110000000000$，负数补码：$0b1111010000000000$

---

### 习题2

一个Q15数 $a=20000$（≈0.61）和另一个Q15数 $b=30000$（≈0.92）相乘，结果再用Q15表示。精确计算并指出是否有信息损失。

**答案**：

$a \times b = 20000 \times 30000 = 600000000$

右移15位：$600000000 >> 15 = 600000000 / 32768 = 18310.55...$

取整：$18310$

验证：$20000/32768 = 0.61035$，$30000/32768 = 0.91553$，乘积精确值 $= 0.55878$

Q15表示：$18310/32768 = 0.55878$ ✓

没有溢出（结果在[-32768, 32767]内）。右移15位时低15位被丢弃，引入了约 $2^{-15}$ 量化的舍入误差，这是定点运算固有的。

---

### 习题3

某工程师在32位浮点MCU上用`double`实现了整个控制算法，理由是"精度越高越好"。请分析这种做法在STM32F407（Cortex-M4F，带单精度FPU，无双精度硬件加速）上的潜在问题。

**答案**：

1. **速度**：Cortex-M4F的FPU只支持单精度（float）硬件加速。`double`运算完全靠软件库，一次乘加可能需要50-200个周期，而`float`只需1-3个周期。

2. **内存**：`double`占8字节，`float`占4字节。如果控制算法有100个状态变量，内存占用翻倍。

3. **精度冗余**：控制算法的传感器精度通常是12-16位，执行器分辨率是8-12位。用64位浮点处理16位精度的信号，好比用千分尺量身高——精度远超需求，徒增开销。

4. **正确做法**：在Cortex-M4F上用`float`，在需要更高精度的特定环节（比如缓慢累积的积分器）用`double`，其余保持`float`。

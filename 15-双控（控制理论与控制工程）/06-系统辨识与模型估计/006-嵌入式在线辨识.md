# 嵌入式在线辨识

## 1. 为什么需要在线辨识？

传统的批量辨识（如 MATLAB 中的 `arx`）要求所有数据先采集完毕，然后一次性处理。但在许多工程场景中，这不可行：

- **自适应控制**：系统参数随时间漂移（电机温度变化、催化剂老化），控制器需要实时更新模型。
- **故障检测**：模型参数的突变可能预示设备故障。
- **嵌入式系统**：无人机、机器人、电动汽车等无法将所有数据传输到上位机处理。

```
离线辨识                          在线辨识
─────────────────────────────────────────────────────────
数据 ──▶ [采集完成] ──▶ [批量计算]    数据 ──▶ [逐点到达]
           全部存储        模型输出              │
                                                ▼
                                          [递推更新]
                                                │
                                                ▼
                                          [实时模型]
                                                │
                                                ▼
                                          [自适应控制]
```

## 2. 嵌入式 RLS 的核心挑战

将 RLS 算法移植到嵌入式平台（MCU、DSP、FPGA）时，面临三大挑战：

| 挑战 | 原因 | 解决方案 |
|------|------|---------|
| 计算资源有限 | MCU 的 FPU 可能很慢或不存在 | 简化算法、定点运算、协处理器 |
| 数值稳定性 | 有限字长导致 $P$ 矩阵退化 | UD 分解、平方根滤波 |
| 存储限制 | $P$ 矩阵随参数数平方增长 | 低阶模型、稀疏结构 |

## 3. 嵌入式 RLS 的优化实现

### 3.1 标准 RLS 的浮点实现 (C)

```c
/* Optimized RLS for embedded systems
 * Model: y(t) = phi^T(t) * theta
 * Supports configurable lambda (forgetting factor)
 */

#include <math.h>
#include <string.h>

#define N_MAX   8       /* max number of parameters */
#define LAMBDA  0.995   /* forgetting factor */
#define P0      1000.0  /* initial covariance diagonal */

typedef struct {
    int n;                  /* number of parameters */
    double theta[N_MAX];    /* parameter estimates */
    double P[N_MAX * N_MAX]; /* covariance matrix (column-major or flat) */
    double lambda;          /* forgetting factor */
} RLS_State;

void rls_init(RLS_State* rls, int n_param, double lambda) {
    rls->n = n_param;
    rls->lambda = lambda;
    memset(rls->theta, 0, sizeof(double) * n_param);
    for (int i = 0; i < n_param; i++) {
        for (int j = 0; j < n_param; j++) {
            rls->P[i * n_param + j] = (i == j) ? P0 : 0.0;
        }
    }
}

/* Matrix-vector multiply: y = A * x, A is n x n */
static void mat_vec_mul(const double* A, const double* x, double* y, int n) {
    for (int i = 0; i < n; i++) {
        y[i] = 0.0;
        for (int j = 0; j < n; j++) {
            y[i] += A[i * n + j] * x[j];
        }
    }
}

/* Dot product */
static double dot(const double* a, const double* b, int n) {
    double s = 0.0;
    for (int i = 0; i < n; i++) s += a[i] * b[i];
    return s;
}

void rls_update(RLS_State* rls, const double* phi, double y) {
    const int n = rls->n;
    double P_phi[N_MAX];      /* P * phi */
    double k[N_MAX];          /* gain vector */
    double denom;
    double e;                 /* prediction error */
    int i, j;

    /* e = y - phi^T * theta */
    e = y;
    for (i = 0; i < n; i++) {
        e -= phi[i] * rls->theta[i];
    }

    /* P_phi = P * phi */
    mat_vec_mul(rls->P, phi, P_phi, n);

    /* denom = lambda + phi^T * P * phi */
    denom = rls->lambda + dot(phi, P_phi, n);

    /* k = P_phi / denom */
    for (i = 0; i < n; i++) {
        k[i] = P_phi[i] / denom;
    }

    /* theta = theta + k * e */
    for (i = 0; i < n; i++) {
        rls->theta[i] += k[i] * e;
    }

    /* P = (P - k * phi^T * P) / lambda */
    /* Compute outer product: k * phi^T, then multiply by P */
    double temp[N_MAX * N_MAX];
    for (i = 0; i < n; i++) {
        for (j = 0; j < n; j++) {
            temp[i * n + j] = k[i] * phi[j];
        }
    }

    double update[N_MAX * N_MAX];
    for (i = 0; i < n; i++) {
        for (j = 0; j < n; j++) {
            update[i * n + j] = 0.0;
            for (int m = 0; m < n; m++) {
                update[i * n + j] += temp[i * n + m] * rls->P[m * n + j];
            }
        }
    }

    for (i = 0; i < n; i++) {
        for (j = 0; j < n; j++) {
            rls->P[i * n + j] = (rls->P[i * n + j] - update[i * n + j]) / rls->lambda;
        }
    }
}
```

### 3.2 计算复杂度分析

对于 $n$ 个参数：

| 操作 | 乘法次数 | 加法次数 |
|------|---------|---------|
| 预测误差 $e$ | $n$ | $n$ |
| $P \phi$ | $n^2$ | $n(n-1)$ |
| $\phi^T P \phi$ | $n$ | $n-1$ |
| 增益 $k$ | $n$ | $0$ |
| 参数更新 | $n$ | $n$ |
| 协方差更新 | $2n^3$ | $2n^3$ |
| **总计** | $O(n^3)$ | $O(n^3)$ |

对于典型的 $n = 4$（二阶 ARX），每次更新约需 $200$ 次浮点运算，在 100 MHz ARM Cortex-M4 上耗时 $< 10 \, \mu$s。

### 3.3 参数冻结机制

在实际系统中，有时需要暂停辨识（如瞬态过程、传感器故障）：

```c
typedef struct {
    RLS_State rls;
    int enabled;        /* 1 = update, 0 = freeze */
    double err_thresh;  /* max acceptable |e| */
} RLS_Adaptive;

void rls_adaptive_update(RLS_Adaptive* ad, const double* phi, double y) {
    if (!ad->enabled) return;

    /* Compute error without updating */
    double e = y;
    for (int i = 0; i < ad->rls.n; i++) {
        e -= phi[i] * ad->rls.theta[i];
    }

    /* If error is suspiciously large, might be fault/disturbance */
    if (fabs(e) > ad->err_thresh) {
        /* Optional: count consecutive violations, then alarm */
        return;  /* skip update */
    }

    rls_update(&ad->rls, phi, y);
}
```

## 4. 定点实现

### 4.1 为什么需要定点？

低端 MCU（如 Cortex-M0）没有硬件 FPU，浮点运算通过软件模拟，速度慢 10-100 倍。定点运算使用整数硬件，速度快且确定性强。

### 4.2 Q15 定点 RLS 框架

```c
/* Fixed-point RLS using Q15 arithmetic
 * Q15: 1 sign bit + 15 fractional bits, range [-1, 1-2^-15]
 * For values outside [-1,1], use scaling factors
 */

#include <stdint.h>

#define Q_SHIFT    15
#define Q_ONE      (1 << Q_SHIFT)   /* 1.0 in Q15 = 32768 */

typedef int16_t q15_t;

/* Multiply two Q15 numbers, result in Q15 */
static inline q15_t q15_mul(q15_t a, q15_t b) {
    int32_t temp = (int32_t)a * (int32_t)b;
    return (q15_t)(temp >> Q_SHIFT);
}

/* Saturated addition */
static inline q15_t q15_add(q15_t a, q15_t b) {
    int32_t temp = (int32_t)a + (int32_t)b;
    if (temp > INT16_MAX) return INT16_MAX;
    if (temp < INT16_MIN) return INT16_MIN;
    return (q15_t)temp;
}

/* RLS state in fixed point */
#define FP_N_MAX   4

typedef struct {
    int n;
    q15_t theta[FP_N_MAX];       /* scaled by K_theta */
    q15_t P[FP_N_MAX * FP_N_MAX]; /* scaled by K_P */
    q15_t lambda;                /* forgetting factor in Q15 */
    int32_t K_theta;             /* theta scaling factor */
    int32_t K_P;                 /* P scaling factor */
} RLS_Fixed;
```

**关键点**：
- $P$ 矩阵元素可能 $> 1$，需要单独的缩放因子 $K_P$。
- 中间计算使用 `int32_t` 防止溢出，然后截断回 `int16_t`。
- 除法（计算增益）是最困难的部分，通常用移位近似或查表法。

## 5. 数值稳定性：UD 分解

### 5.1 问题

标准 RLS 中，$P$ 矩阵在有限精度下会逐渐失去正定性，导致算法发散。

### 5.2 UD 分解

将 $P$ 分解为：

$$
P = U D U^T
$$

其中 $U$ 是单位上三角矩阵，$D$ 是对角矩阵。直接递推 $U$ 和 $D$ 而不是 $P$，数值稳定性大大提高。

### 5.3 UD-RLS 算法概要

```
Initialize:
    U = I, D = diag(P0, P0, ..., P0)

At each step:
    1. f = U^T * phi
    2. v = D * f
    3. alpha_0 = lambda
    4. For j = 1 to n:
           alpha_j = alpha_{j-1} + v_j * f_j
           D_jj_new = D_jj * alpha_{j-1} / alpha_j / lambda
           For i = 1 to j-1:
               U_ij_new = U_ij - v_i * f_j / alpha_{j-1}
           k_j = v_j / alpha_j
    5. theta = theta + k * e
```

UD-RLS 的计算复杂度与标准 RLS 相同（$O(n^3)$），但数值稳定性好得多，是工业嵌入式系统的首选。

## 6. 数值示例：时变系统的在线跟踪

### 6.1 问题设定

真实系统的参数在 $t = 500$ 时发生突变：

$$
y(t) = \begin{cases}
0.8 \, y(t-1) + 0.2 \, u(t-1) + e(t), & t < 500 \\
0.4 \, y(t-1) + 0.6 \, u(t-1) + e(t), & t \geq 500
\end{cases}
$$

我们使用带遗忘因子的 RLS ($\lambda = 0.98$) 在线跟踪参数变化。

### 6.2 Python 仿真

```python
import numpy as np
import matplotlib.pyplot as plt

N = 1000
np.random.seed(42)
u = np.random.uniform(-1, 1, N)
e = 0.05 * np.random.randn(N)

# Time-varying true parameters
a_true = np.zeros(N)
b_true = np.zeros(N)
a_true[:500] = 0.8
a_true[500:] = 0.4
b_true[:500] = 0.2
b_true[500:] = 0.6

# Simulate
y = np.zeros(N)
for t in range(1, N):
    y[t] = a_true[t] * y[t-1] + b_true[t] * u[t-1] + e[t]

# RLS with forgetting
lambda_f = 0.98
theta = np.zeros(2)   # [a, b]
P = 100.0 * np.eye(2)

a_est = np.zeros(N)
b_est = np.zeros(N)

for t in range(1, N):
    phi = np.array([y[t-1], u[t-1]])
    eps = y[t] - phi @ theta
    denom = lambda_f + phi @ P @ phi
    k = (P @ phi) / denom
    theta = theta + k * eps
    P = (1.0 / lambda_f) * (P - np.outer(k, phi @ P))
    # Symmetrize for stability
    P = 0.5 * (P + P.T)
    a_est[t] = theta[0]
    b_est[t] = theta[1]

# Plot
fig, axes = plt.subplots(2, 1, figsize=(10, 6), sharex=True)
axes[0].plot(a_true, 'k-', lw=2, label='True a')
axes[0].plot(a_est, 'r-', lw=1, label='Estimated a')
axes[0].axvline(500, color='g', ls='--', alpha=0.5, label='Parameter jump')
axes[0].set_ylabel('a')
axes[0].legend()
axes[0].grid(True)

axes[1].plot(b_true, 'k-', lw=2, label='True b')
axes[1].plot(b_est, 'r-', lw=1, label='Estimated b')
axes[1].axvline(500, color='g', ls='--', alpha=0.5)
axes[1].set_ylabel('b')
axes[1].set_xlabel('Time step')
axes[1].legend()
axes[1].grid(True)

plt.suptitle('RLS Tracking of Time-Varying Parameters (λ=0.98)')
plt.tight_layout()
plt.savefig('rls_tracking.png', dpi=150)
plt.show()
```

### 6.3 结果解读

图像会显示：
- 在 $t < 500$ 时，估计值快速收敛到 $(0.8, 0.2)$。
- 在 $t = 500$ 突变后，估计值在大约 50-100 个采样点内重新收敛到 $(0.4, 0.6)$。
- 收敛速度与遗忘因子 $\lambda$ 直接相关：$\lambda$ 越小，收敛越快，但稳态波动也越大。

## 7. 常见错误与纠正

### 错误 1：协方差矩阵 "爆炸" (Covariance Wind-up)

**场景**：在自适应控制中，当设定点长时间不变时，输入信号 $u(t)$ 几乎恒定，回归向量 $\varphi(t)$ 的信息量极低。

**问题**：RLS 的 $P$ 矩阵持续被 $1/\lambda$ 放大（因为 $\varphi^T P \varphi \approx 0$，导致 $P_t \approx P_{t-1}/\lambda$），最终 $P$ 变得极大。一旦有扰动，参数估计会剧烈震荡。

**纠正**：
1. **变量遗忘因子**：当预测误差小时增大 $\lambda$（接近 1），误差大时减小 $\lambda$。
2. **协方差重置**：当检测到 $P$ 的迹超过阈值时，重置 $P$ 为初始值。
3. **恒定迹算法**：强制 $\text{tr}(P_t) = \text{const}$，动态调整增益。

```python
# Variable forgetting factor
def rls_vff(y, u, phi, theta, P, e_prev, lambda_min=0.9, lambda_max=0.999):
    eps = y - phi @ theta
    # Increase lambda when error is small (low information)
    # Decrease lambda when error is large (new information)
    error_ratio = abs(eps) / (abs(e_prev) + 1e-6)
    lam = np.clip(lambda_max - 0.1 * error_ratio, lambda_min, lambda_max)
    # ... standard RLS update with variable lam ...
    return theta, P, eps, lam
```

### 错误 2：未考虑执行器饱和

**场景**：在自适应控制系统中，控制器输出达到了执行器的物理极限（如电机电压饱和）。

**问题**：辨识算法继续根据控制器输出（而非实际作用于系统的输入）更新模型。这导致辨识出的模型不是真实系统，而是"系统 + 饱和非线性"。

**纠正**：
1. 将**实际执行器输出**（而非控制器指令）作为辨识的输入 $u(t)$；
2. 在检测到饱和时暂停辨识；
3. 在控制律中引入抗饱和 (Anti-windup) 机制。

```c
/* Use actual actuator output, not controller command */
double u_actual = read_actuator_output();  /* e.g., measured PWM voltage */
rls_update(&rls, phi, y, u_actual);        /* NOT the unsaturated command */
```

## 8. 自测习题

**习题 1**：在线 RLS 中，遗忘因子 $\lambda$ 的选择需要在"跟踪速度"和"噪声抑制"之间权衡。请分别分析 $\lambda = 0.9$ 和 $\lambda = 0.999$ 在一个参数缓慢漂移的系统中的表现差异。

<details>
<summary>答案</summary>

**$\lambda = 0.9$**：
- 有效记忆长度约 $1/(1-0.9) = 10$ 个采样点。
- **跟踪速度**：极快，能在 10-20 个采样点内跟上参数变化。
- **噪声抑制**：差，估计值会持续剧烈波动，因为旧数据被快速遗忘，噪声的影响无法被平均掉。
- **适用场景**：参数快速变化的系统，或作为变化检测的前端。

**$\lambda = 0.999$**：
- 有效记忆长度约 $1/(1-0.999) = 1000$ 个采样点。
- **跟踪速度**：慢，需要数百个采样点才能跟上变化。
- **噪声抑制**：极好，噪声被大量数据平均，估计值平滑。
- **适用场景**：参数几乎不变的系统，或信噪比很低的环境。

工程折中通常取 $\lambda \in [0.95, 0.995]$。

</details>

**习题 2**：UD 分解为什么比直接维护 $P$ 矩阵更数值稳定？简述其原理。

<details>
<summary>答案</summary>

UD 分解将 $P = U D U^T$，其中 $U$ 是单位上三角矩阵，$D$ 是对角矩阵。

**数值稳定的原因**：
1. **正定性保持**：$D$ 的对角元素必须为正。在递推过程中，如果某个 $D_{jj}$ 变为负值或零，立即可以检测并修正（如重置为一个小正值）。
2. **条件数改善**：$U$ 和 $D$ 的动态范围比 $P$ 本身小得多。$P$ 的元素可能相差多个数量级，导致浮点运算中的精度损失；而 $U$（接近单位矩阵）和 $D$（对角元素）的条件数更可控。
3. **避免矩阵求逆**：UD-RLS 直接递推 $U$ 和 $D$，不需要显式计算 $P^{-1}$。

</details>

**习题 3**：在嵌入式自适应控制中，如果 MCU 只有 16 位定点 ALU（无 FPU），实现 RLS 时最大的难点是什么？给出至少两个解决方案。

<details>
<summary>答案</summary>

**最大难点**：
1. **动态范围不足**：$P$ 矩阵的初始值可能为 $10^3$，运行中可能缩小到 $10^{-3}$，16 位 Q15 格式的动态范围只有约 $10^{-5} \sim 1$，无法覆盖。
2. **除法运算**：RLS 中的标量除法 ($1 / \text{denom}$) 在定点中极慢且精度差。
3. **溢出风险**：矩阵乘法中的累加容易溢出 16 位。

**解决方案**：
1. **分块缩放**：对 $P$ 的不同区域使用不同的缩放因子，或动态调整全局缩放。
2. **32 位中间计算**：即使最终存储用 16 位，所有乘加运算在 32 位中进行，最后截断。
3. **简化算法**：使用梯度下降法 (LMS) 替代 RLS。LMS 复杂度为 $O(n)$ 而非 $O(n^3)$，且不需要维护协方差矩阵。
4. **查表法除法**：预计算倒数表，用乘法替代除法。

</details>

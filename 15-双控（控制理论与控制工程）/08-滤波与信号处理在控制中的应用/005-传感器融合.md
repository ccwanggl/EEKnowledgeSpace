# 传感器融合

> 没有任何一个传感器是完美的。GPS 有漂移但无累积误差，IMU 无漂移但会积分发散，摄像头分辨率高但受光照限制，激光雷达精确但稀疏。传感器融合的使命，是将这些"有缺陷的见证者"的证言，组合成一个比任何单一传感器都更可靠、更完整的估计。

---

## 1. 为什么需要传感器融合

### 1.1 单一传感器的局限性

```
传感器能力雷达图（示意）

      精度
        ^
       /|\
      / | \
   带宽  +---> 鲁棒性
      \ | /
       \|/
        v
      成本

GPS:    精度高，鲁棒性中，带宽低（1Hz），成本低
IMU:    精度中，鲁棒性高，带宽高（1kHz），成本中
Camera: 精度高，鲁棒性低，带宽中，成本低
LiDAR:  精度极高，鲁棒性中，带宽中，成本高
```

单一传感器在任何实际环境中都会遇到**失效模式（failure mode）**：

| 传感器 | 失效场景 | 后果 |
|-------|---------|-----|
| GPS | 城市峡谷、隧道、室内 | 信号丢失或反射导致多路径误差 |
| IMU | 长时间运行 | 积分漂移，姿态误差发散 |
| Camera | 夜间、强光、运动模糊 | 特征跟踪失败 |
| LiDAR | 雨雾、高反射表面 | 点云退化 |
| 超声波 | 温湿度变化、吸声材料 | 测距误差剧增 |

**融合的核心价值**：利用多传感器的**互补性**和**冗余性**，在任一传感器失效时仍能维持可接受的估计质量。

## 2. 融合架构的分类

### 2.1 按抽象层次分类

```
+---------------------------------------------------+
|                   决策级融合                        |
|    每个传感器独立做决策，然后投票/融合               |
|    例：多摄像头目标识别，各自输出 bbox 再 NMS       |
+---------------------------------------------------+
|                   特征级融合                        |
|    提取各传感器的特征向量，在特征空间融合            |
|    例：图像 CNN 特征 + 点云 Voxel 特征拼接          |
+---------------------------------------------------+
|                   数据级融合                        |
|    直接融合原始测量数据                              |
|    例：卡尔曼滤波、互补滤波                          |
+---------------------------------------------------+
         信息损失小 <----------------> 计算/通信开销小
```

控制系统中的传感器融合通常发生在**数据级**或**低层特征级**，因为控制回路需要低延迟、高频率的估计输出。

### 2.2 按时间对齐方式分类

| 架构 | 描述 | 适用场景 |
|-----|------|---------|
| 集中式融合 | 所有原始数据送到中央处理器统一处理 | 计算资源充足，传感器数量少 |
| 分布式融合 | 各传感器先做局部估计，再交换估计结果 | 传感器节点分散，通信带宽受限 |
| 联邦式融合 | 混合架构，局部节点做预处理，中央做最终融合 | 大规模系统（如自动驾驶车队） |

## 3. 数据级融合的核心方法

### 3.1 加权平均融合

最简单的融合方法。若有 $N$ 个传感器测量同一量 $x$，各自测量为 $z_i$，方差为 $\sigma_i^2$：

**最优加权（最小方差无偏估计）**：

$$
\hat{x} = \sum_{i=1}^{N} w_i z_i, \quad w_i = \frac{\sigma_i^{-2}}{\sum_{j=1}^{N} \sigma_j^{-2}}
$$

融合后的估计方差：

$$
\sigma_{\hat{x}}^2 = \left(\sum_{i=1}^{N} \sigma_i^{-2}\right)^{-1}
$$

**关键性质**：融合方差**严格小于**任何单一传感器的方差。

**数值示例**：两个测距传感器测量同一距离：
- 传感器 A：$z_A = 10.2\,\text{m}$，$\sigma_A = 0.5\,\text{m}$
- 传感器 B：$z_B = 9.8\,\text{m}$，$\sigma_B = 0.2\,\text{m}$

权重：

$$
w_A = \frac{1/0.25}{1/0.25 + 1/0.04} = \frac{4}{4 + 25} = 0.138
$$

$$
w_B = \frac{25}{29} = 0.862
$$

融合结果：

$$
\hat{x} = 0.138 \times 10.2 + 0.862 \times 9.8 = 9.855\,\text{m}
$$

$$
\sigma_{\hat{x}} = \sqrt{\frac{1}{4 + 25}} = \sqrt{0.0345} \approx 0.186\,\text{m}
$$

传感器 B 更精确，因此获得了更大的权重，融合结果也更接近 B 的读数。

### 3.2 协方差交叉（Covariance Intersection）

当传感器的估计误差**相关**时（例如两个 GPS 接收器都受同一颗卫星时钟误差影响），标准卡尔曼融合的假设被破坏。协方差交叉提供了一种保守但稳健的融合方法。

给定两个估计 $(\hat{x}_A, \mathbf{P}_A)$ 和 $(\hat{x}_B, \mathbf{P}_B)$，协方差交叉输出：

$$
\mathbf{P}_{CI}^{-1} = \omega \mathbf{P}_A^{-1} + (1-\omega) \mathbf{P}_B^{-1}
$$

$$
\hat{x}_{CI} = \mathbf{P}_{CI}\left(\omega \mathbf{P}_A^{-1}\hat{x}_A + (1-\omega)\mathbf{P}_B^{-1}\hat{x}_B\right)
$$

其中 $\omega \in [0,1]$ 通过优化某个准则（如最小化 $\det(\mathbf{P}_{CI})$）选择。

**与标准卡尔曼融合的区别**：
- 卡尔曼融合假设误差互不相关：$\mathbf{P}_{fuse}^{-1} = \mathbf{P}_A^{-1} + \mathbf{P}_B^{-1}$
- CI 不假设独立性，结果更保守（方差更大），但**保证一致性**（实际误差不大于估计方差）

### 3.3 异步多速率融合

实际系统中，传感器以不同频率输出数据：

| 传感器 | 输出频率 | 延迟 |
|-------|---------|-----|
| IMU | $1\,\text{kHz}$ | $1\,\text{ms}$ |
| Camera | $30\,\text{Hz}$ | $33\,\text{ms}$ |
| GPS | $10\,\text{Hz}$ | $100\,\text{ms}$ |

**处理策略**：

```
时间轴:
t=0    t=1ms  ...  t=30ms  ...  t=100ms  ...
 |       |            |             |
 IMU    IMU         Camera        GPS
 更新    更新         更新          更新
 (高频)  (高频)      (触发融合)     (触发融合)

融合触发策略:
- 每个高频步：仅用 IMU 做预测（状态传播）
- Camera 到达：用视觉测量更新
- GPS 到达：用 GPS 测量更新
```

这种异步卡尔曼滤波结构在多传感器 SLAM 和组合导航中极为常见。

## 4. 典型融合系统：GPS/INS 组合导航

### 4.1 系统架构

```
+-----------+      +----------+      +-----------+
|   IMU     |----->|  Strap-  |----->|  INS      |
| (acc,gyro)|      | down     |      |  Solution |
+-----------+      | Integr-  |      | (pos,vel, |
                   | ation    |      |  att)     |
                   +----------+      +-----+-----+
                                         |
+-----------+      +----------+          v
|   GPS     |----->|  GNSS    |----->|  Kalman   |---> Corrected
| Receiver  |      |  Engine  |      |  Filter   |     State
+-----------+      +----------+      +-----+-----+
                                         |
                                    (error feedback
                                     to INS)
```

### 4.2 松耦合 vs 紧耦合

| 特性 | 松耦合（Loose） | 紧耦合（Tight） |
|-----|---------------|---------------|
| 融合层级 | GPS 输出位置/速度后才融合 | 融合发生在伪距/载波相位级 |
| GPS 失效鲁棒性 | 差（GPS 完全丢失则无法修正） | 好（单颗卫星信号也可利用） |
| 计算复杂度 | 低 | 高 |
| 精度 | 中 | 高 |
| 典型应用 | 车载导航、无人机 | 测绘、精准农业、自动驾驶 |

### 4.3 误差状态卡尔曼滤波

在 GPS/INS 融合中，通常不直接估计导航状态（位置、速度、姿态），而是估计**误差状态**（位置误差、速度误差、姿态误差、IMU 零偏误差等）。

**优势**：
1. 误差状态是**小量**，线性化更准确
2. 主导动态由 INS 积分承担，卡尔曼滤波只负责**修正**
3. 数值稳定性更好

误差状态向量：

$$
\delta\mathbf{x} = \begin{bmatrix} \delta\mathbf{p} & \delta\mathbf{v} & \delta\boldsymbol{\psi} & \delta\mathbf{b}_a & \delta\mathbf{b}_g \end{bmatrix}^T
$$

卡尔曼滤波更新后，修正 INS 输出：

$$
\mathbf{x}_{INS} \leftarrow \mathbf{x}_{INS} - \delta\hat{\mathbf{x}}
$$

然后重置误差状态为零。

## 5. Python 实现：异步多传感器融合框架

```python
import numpy as np
from dataclasses import dataclass
from typing import Optional

@dataclass
class SensorReading:
    timestamp: float
    value: np.ndarray
    covariance: np.ndarray
    sensor_id: str

class AsyncMultiSensorFusion:
    """
    Asynchronous multi-sensor fusion using EKF-like update.
    Handles sensors with different update rates.
    """
    def __init__(self, x0: np.ndarray, P0: np.ndarray,
                 A: np.ndarray, Q: np.ndarray):
        """
        Args:
            x0: initial state
            P0: initial covariance
            A: state transition matrix (discrete)
            Q: process noise covariance
        """
        self.x = x0.copy()
        self.P = P0.copy()
        self.A = A
        self.Q = Q
        self.last_update_time = 0.0
        
    def predict(self, current_time: float):
        """Propagate state to current_time."""
        dt = current_time - self.last_update_time
        if dt <= 0:
            return
        # Simple prediction: x = A*x (assume A already discretized for dt)
        self.x = self.A @ self.x
        self.P = self.A @ self.P @ self.A.T + self.Q
        self.last_update_time = current_time
        
    def update(self, reading: SensorReading,
               H: np.ndarray) -> np.ndarray:
        """
        Fuse a sensor reading.
        
        Args:
            reading: sensor measurement with covariance
            H: observation matrix for this sensor
        
        Returns:
            updated state estimate
        """
        # Ensure state is propagated to measurement time
        self.predict(reading.timestamp)
        
        z = reading.value
        R = reading.covariance
        
        # Kalman update
        S = H @ self.P @ H.T + R
        K = self.P @ H.T @ np.linalg.inv(S)
        
        innovation = z - H @ self.x
        self.x = self.x + K @ innovation
        self.P = (np.eye(len(self.x)) - K @ H) @ self.P
        
        return self.x.copy()


# Example: 1D position estimation with GPS + IMU
# State: [position, velocity, accel_bias]
Ts_imu = 0.001  # 1kHz
A = np.array([[1.0, Ts_imu, 0.0],
              [0.0, 1.0,  Ts_imu],
              [0.0, 0.0,  1.0]])
Q = np.diag([0.001, 0.01, 0.0001])

fusion = AsyncMultiSensorFusion(
    x0=np.array([0.0, 0.0, 0.0]),
    P0=np.diag([1.0, 1.0, 0.1]),
    A=A, Q=Q
)

# IMU update: measures acceleration (indirectly velocity change)
H_imu = np.array([[0.0, 0.0, 1.0]])  # observe acceleration bias through residual

# GPS update: measures position
H_gps = np.array([[1.0, 0.0, 0.0]])

# Simulate asynchronous arrivals
# At t=0.1s: GPS reading arrives
gps_reading = SensorReading(
    timestamp=0.1,
    value=np.array([1.05]),  # measured position
    covariance=np.array([[0.25]]),  # GPS std = 0.5m
    sensor_id="gps"
)
fusion.update(gps_reading, H_gps)

# At t=0.100s: IMU reading arrives (high frequency, after prediction)
imu_reading = SensorReading(
    timestamp=0.100,
    value=np.array([0.01]),  # measured accel residual
    covariance=np.array([[0.001]]),
    sensor_id="imu"
)
# Note: real IMU fusion is more complex; this is simplified illustration
```

## 6. 常见错误与纠正

### 错误 1：忽略传感器之间的相关性

**现象**：两个 GPS 接收器融合后的位置估计方差异常小，但实际定位误差远大于估计方差——滤波器过度自信。

**原因**：两个接收器可能共享相同误差源（同一组卫星、同一电离层延迟模型），它们的误差高度相关。标准卡尔曼融合假设误差独立，导致协方差估计过于乐观。

**纠正方法**：
1. **协方差交叉（CI）**：不假设独立性，给出保守估计
2. **显式建模相关性**：估计联合协方差矩阵的非对角元素
3. **识别共同模式**：识别并扣除共同误差源（如通过双差分消除电离层误差）

**数值说明**：若两个传感器误差相关系数为 $\rho = 0.9$，融合方差应为：

$$
\sigma_{fuse}^2 = \frac{\sigma_1^2 \sigma_2^2 (1-\rho^2)}{\sigma_1^2 + \sigma_2^2 - 2\rho\sigma_1\sigma_2}
$$

而非独立假设下的 $\sigma_{fuse}^2 = (\sigma_1^{-2} + \sigma_2^{-2})^{-1}$。当 $\rho \to 1$ 时，融合增益趋近于零——两个完全相关的测量不提供额外信息。

### 错误 2：时间戳不一致导致融合发散

**现象**：系统在多传感器融合后状态估计发散，或出现周期性跳变。

**原因**：不同传感器的测量时间戳未精确对齐。例如，GPS 接收机报告的时间是信号接收时刻，但数据通过 UART 传输到主控有 $50\,\text{ms}$ 延迟。若未补偿此延迟，相当于将"过去"的测量当作"现在"使用。

**纠正方法**：
1. **硬件时间同步**：使用 PPS（Pulse Per Second）信号对齐 GPS 与系统时钟
2. **传输延迟标定**：测量并补偿每个传感器的端到端延迟
3. **时间戳校正公式**：

$$
t_{true} = t_{reported} - \tau_{sensor} - \tau_{transmission} - \tau_{processing}
$$

4. **缓冲与插值**：维护状态历史缓冲区，在任意时刻 $t$ 可通过插值获得状态估计

```python
class TimestampSynchronizer:
    """Buffer and interpolate state history for time-aligned fusion."""
    def __init__(self, max_history: float = 1.0):
        self.history = []  # list of (timestamp, state, covariance)
        self.max_history = max_history
        
    def add_state(self, t: float, x: np.ndarray, P: np.ndarray):
        self.history.append((t, x.copy(), P.copy()))
        # Remove old entries
        cutoff = t - self.max_history
        self.history = [(ti, xi, Pi) for ti, xi, Pi in self.history if ti >= cutoff]
        
    def get_state_at(self, t_query: float):
        """Linear interpolation of state at given time."""
        # Find bracketing timestamps
        times = [hi[0] for hi in self.history]
        if t_query <= times[0]:
            return self.history[0][1], self.history[0][2]
        if t_query >= times[-1]:
            return self.history[-1][1], self.history[-1][2]
        
        for i in range(len(times)-1):
            if times[i] <= t_query <= times[i+1]:
                alpha = (t_query - times[i]) / (times[i+1] - times[i])
                x_interp = (1-alpha) * self.history[i][1] + alpha * self.history[i+1][1]
                return x_interp, self.history[i][2]
```

## 7. 自测习题

### 习题 1
三个传感器测量同一温度，测量值和方差分别为：$z_1 = 25.0°C, \sigma_1^2 = 0.04$；$z_2 = 25.3°C, \sigma_2^2 = 0.01$；$z_3 = 24.8°C, \sigma_3^2 = 0.09$。求最优加权融合结果及其方差。

<details>
<summary>点击查看答案</summary>

权重：

$w_1 = \frac{1/0.04}{1/0.04 + 1/0.01 + 1/0.09} = \frac{25}{25 + 100 + 11.11} = \frac{25}{136.11} = 0.184$

$w_2 = \frac{100}{136.11} = 0.735$

$w_3 = \frac{11.11}{136.11} = 0.082$

融合结果：

$\hat{T} = 0.184 \times 25.0 + 0.735 \times 25.3 + 0.082 \times 24.8 = 4.60 + 18.40 + 2.03 = 25.03°C$

融合方差：

$\sigma_{\hat{T}}^2 = (25 + 100 + 11.11)^{-1} = 1/136.11 = 0.00735$

$\sigma_{\hat{T}} = 0.086°C$

可见融合方差远小于任何单一传感器（最小为 $\sigma_2 = 0.1°C$）。

</details>

### 习题 2
两个传感器的估计为 $\hat{x}_A = 5.0, P_A = 4$ 和 $\hat{x}_B = 6.0, P_B = 1$。
(1) 用标准卡尔曼融合（假设独立）求融合结果；
(2) 用协方差交叉（取 $\omega = 0.5$）求融合结果；
(3) 比较两种方法的结果差异并解释。

<details>
<summary>点击查看答案</summary>

(1) 标准卡尔曼融合：

$P_{fuse}^{-1} = P_A^{-1} + P_B^{-1} = 0.25 + 1 = 1.25 \Rightarrow P_{fuse} = 0.8$

$\hat{x}_{fuse} = P_{fuse}(P_A^{-1}\hat{x}_A + P_B^{-1}\hat{x}_B) = 0.8(0.25 \times 5 + 1 \times 6) = 0.8(1.25 + 6) = 5.8$

(2) 协方差交叉（$\omega = 0.5$）：

$P_{CI}^{-1} = 0.5 \times 0.25 + 0.5 \times 1 = 0.625 \Rightarrow P_{CI} = 1.6$

$\hat{x}_{CI} = P_{CI}(0.5 \times 0.25 \times 5 + 0.5 \times 1 \times 6) = 1.6(0.625 + 3) = 5.8$

(3) 两种方法给出的点估计相同（$5.8$），但协方差交叉的方差估计（$1.6$）远大于卡尔曼融合的方差估计（$0.8$）。CI 更保守，因为它不假设独立性，为可能的相关误差留出了余量。

</details>

### 习题 3
在 GPS/INS 紧耦合系统中，为什么即使只有 3 颗 GPS 卫星可见（不足以解算独立定位），系统仍然可以提供一定精度的导航信息？

<details>
<summary>点击查看答案</summary>

紧耦合系统在伪距/载波相位层面融合，而非位置层面。

即使只有 3 颗卫星（通常需要 4 颗才能独立解算 3D 位置 + 钟差），INS 可以提供**先验约束**：
- INS 预测的位置和钟差漂移将搜索空间大幅缩小
- 3 颗卫星的伪距观测 + INS 先验 = 可解的融合问题

此外，INS 的速度估计可以提供额外的运动学约束。这在城市峡谷等 GPS 信号受限环境中至关重要——松耦合系统在此场景会直接失效，而紧耦合系统可以"撑过"短暂的卫星不足期。

</details>

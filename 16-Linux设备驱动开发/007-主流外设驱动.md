# 主流外设驱动

GPIO 只涉及板内信号；I2C/SPI 才是外设驱动的主战场——传感器、ADC、Flash、显示驱动芯片几乎都在这两条总线上。协议本身见 [[05-Communication/02-I2C-SPI-UART/004-I2C总线与多设备仲裁|I2C 总线]]与 [[05-Communication/02-I2C-SPI-UART/003-SPI同步串行接口|SPI 接口]]，本文以 I2C/SPI 传感器为主线讲透主流外设驱动的通用方法论，其它子系统同法推演（见下文地图）。

## 主流外设驱动地图

I2C/SPI 传感器是"通用总线 + 芯片时序"类驱动，方法论本文覆盖；嵌入式产品中的其它外设则接入各自的标准子系统——**驱动模型（[[003-Linux设备模型|003]]）相同，只是方法表换成子系统规定的接口**：

| 外设 | 子系统 | 说明 |
|------|--------|------|
| 按键/键盘/触摸屏 | input | `input_allocate_device` + `input_report_key` |
| LED/背光 | leds / backlight | 亮度接口标准化 |
| 温湿度等传感器 | **iio / hwmon** | 连续采样型传感器的事实标准，sysfs 一次一测的升级版 |
| ADC/DAC | iio | 通道、刻度、触发器统一管理 |
| RTC / 看门狗 / PWM | rtc / wdt / pwm | 框架简单，dedicated API |
| 显示 / 触摸 | drm / input | DRM 是显示驱动主干（MIPI/HDMI 面板） |
| 音频 | ALSA（ASoC） | Machine/Driver/Codec 三段式 |
| 网络 / USB 设备 | mdio-usb-net / usb | 接更底层的总线框架 |

遇到新外设的工作流：查 bindings 文档（`Documentation/devicetree/bindings/`）→ 找内核内同类驱动抄骨架 → 套 003 的模型。本文的 I2C/SPI 两例就是这个流程的示范。

## 先用户态验证，再写驱动

总线驱动（`i2c-rockchip`/`spi-rockchip`）由 SoC 厂商维护、随内核自带，设备驱动只管自己那片芯片。**动手写驱动前先用用户态工具把硬件验证一遍**，把"接线问题"和"代码问题"分开：

```bash
sudo i2cdetect -y 1            # 扫描 i2c-1 总线，SHT30 应出现在 0x44/0x45
sudo i2cget -y 1 0x44 0x24 w   # 单字节试探（读寄存器）
ls /dev/spidev*                # SPI 控制器 + spidev 是否就绪
```

`i2cdetect` 扫描时无响应地址显示 `--`，有响应显示地址（7 位地址制式）。这一步过不了，查接线、上拉电阻、供电，不要怀疑驱动代码。

## I2C：以 SHT30 温湿度传感器为例

SHT30 是单芯片 I2C 传感器：发 2 字节测量命令，回 6 字节（温度 16bit + CRC + 湿度 16bit + CRC），常见模块地址 `0x44`（ADDR 脚接地）。这是传感器驱动的标准形态。

### 设备树

```dts
&i2c1 {
    status = "okay";
    pinctrl-names = "default";
    pinctrl-0 = <&i2c1m1_xfer>;          /* 引脚复用组名以 rk3588 dtsi 为准 */

    sht30@44 {
        compatible = "myvendor,sht30";
        reg = <0x44>;                    /* I2C 地址，子节点必备 */
    };
};
```

`reg` 是 i2c 子节点的**地址**（不是寄存器），i2c 核心据此创建 `i2c_client`。compatible 命中后回调驱动的 probe。

### 驱动代码

```c
#include <linux/module.h>
#include <linux/i2c.h>
#include <linux/crc8.h>
#include <linux/delay.h>
#include <linux/device.h>

struct sht30 {
    struct i2c_client *client;
    u8 crc_table[CRC8_TABLE_SIZE];
};

static int sht30_measure(struct sht30 *priv, int *temp_milli, int *humi_milli)
{
    struct i2c_client *client = priv->client;
    u8 cmd[2] = { 0x24, 0x00 };      /* 单次测量：高重复性、禁止时钟延展 */
    u8 raw[6];
    int ret, t_ticks, h_ticks;

    ret = i2c_master_send(client, cmd, sizeof(cmd));
    if (ret < 0)
        return ret;

    msleep(15);                      /* 高重复性转换时间约 15 ms */

    ret = i2c_master_recv(client, raw, sizeof(raw));
    if (ret != sizeof(raw))
        return ret < 0 ? ret : -EIO;

    /* CRC-8（多项式 0x31，初值 0xFF），分别校验温度、湿度两帧 */
    if (crc8(priv->crc_table, raw, 2, 0xFF) != raw[2] ||
        crc8(priv->crc_table, raw + 3, 2, 0xFF) != raw[5])
        return -EBADMSG;

    t_ticks = (raw[0] << 8) | raw[1];
    h_ticks = (raw[3] << 8) | raw[4];
    *temp_milli = -45000 + 175000 * t_ticks / 65535;   /* datasheet 公式 ×1000 */
    *humi_milli = 100000 * h_ticks / 65535;
    return 0;
}

static ssize_t temperature_show(struct device *dev,
                                struct device_attribute *attr, char *buf)
{
    struct sht30 *priv = dev_get_drvdata(dev);
    int t, h, ret;

    ret = sht30_measure(priv, &t, &h);
    if (ret)
        return ret;
    return sysfs_emit(buf, "%d.%03d\n", t / 1000, abs(t % 1000));
}
static DEVICE_ATTR_RO(temperature);

static ssize_t humidity_show(struct device *dev,
                             struct device_attribute *attr, char *buf)
{
    struct sht30 *priv = dev_get_drvdata(dev);
    int t, h, ret;

    ret = sht30_measure(priv, &t, &h);
    if (ret)
        return ret;
    return sysfs_emit(buf, "%d.%03d\n", h / 1000, abs(h % 1000));
}
static DEVICE_ATTR_RO(humidity);

static struct attribute *sht30_attrs[] = {
    &dev_attr_temperature.attr,
    &dev_attr_humidity.attr,
    NULL
};
ATTRIBUTE_GROUPS(sht30);             /* 生成 sht30_groups，devm 注册 */

static int sht30_probe(struct i2c_client *client, const struct i2c_device_id *id)
{
    struct sht30 *priv;
    int ret;

    if (!i2c_check_functionality(client->adapter, I2C_FUNC_I2C))
        return -ENODEV;

    priv = devm_kzalloc(&client->dev, sizeof(*priv), GFP_KERNEL);
    if (!priv)
        return -ENOMEM;

    priv->client = client;
    crc8_populate_msb(priv->crc_table, 0x31);

    /* 上电自检：读一次，总线上无此芯片则在此失败 */
    {
        int t, h;
        ret = sht30_measure(priv, &t, &h);
        if (ret)
            return dev_err_probe(&client->dev, ret, "no SHT30 response\n");
    }

    i2c_set_clientdata(client, priv);
    ret = devm_device_add_groups(&client->dev, sht30_groups);
    if (ret)
        return ret;

    dev_info(&client->dev, "SHT30 ready\n");
    return 0;
}

static int sht30_remove(struct i2c_client *client)
{
    return 0;
}

static const struct of_device_id sht30_of_match[] = {
    { .compatible = "myvendor,sht30" },
    { }
};
MODULE_DEVICE_TABLE(of, sht30_of_match);

static struct i2c_driver sht30_driver = {
    .probe    = sht30_probe,
    .remove   = sht30_remove,
    .driver   = {
        .name           = "sht30",
        .of_match_table = sht30_of_match,
    },
};
module_i2c_driver(sht30_driver);
MODULE_LICENSE("GPL");
```

驱动骨架与 [[003-Linux设备模型|设备模型]]的 platform 驱动完全一致，差异只在三点：`probe` 收到的是 `i2c_client`（带着总线适配器和地址）；总线操作走 `i2c_master_send/recv` 或 `i2c_transfer`（可多段消息一次总线事务）；注册用 `module_i2c_driver`。内核 5.14+ 为纯 OF 驱动提供 `probe_new`（无 id 表参数），写法更简。

设计点：

- **probe 里做自检**：读一次芯片 ID/状态，无响应直接失败，让"硬件没焊好"在加载时刻暴露，而不是等到用户态读取。
- **CRC 校验不可省**：I2C 有 ACK 但不保证数据内容正确（干扰、时钟延展异常），传感器 datasheet 给的 CRC 要在驱动里验。
- **sysfs 一个属性一次测量**：读 `temperature` 触发一次转换，符合"读即测"的 sysfs 语义；需要连续采样应走 `iio` 框架（工业传感器标准接口），那是进阶方向。

## SPI：时序由芯片决定

SPI 没有设备地址和 ACK，片选、时钟极性/相位、帧格式全由从机芯片的 datasheet 定义，所以 SPI 驱动的核心是把 datasheet 时序翻译成 `spi_message`。

### 设备树

```dts
&spi1 {
    status = "okay";
    pinctrl-names = "default";
    pinctrl-0 = <&spi1m1_pins>;          /* 组名以 dtsi 为准 */
    cs-gpios = <&gpio4 RK_PB0 GPIO_ACTIVE_LOW>;   /* 用 GPIO 做片选（控制器原生 CS 不够时） */

    myadc@0 {
        compatible = "myvendor,myadc";
        reg = <0>;                       /* 第 0 个片选 */
        spi-max-frequency = <10000000>;  /* 从机最大时钟，必备属性 */
    };
};
```

### 内核驱动骨架

```c
static int myadc_read_id(struct spi_device *spi, u16 *id)
{
    u8 tx[4] = { 0x9F, 0, 0, 0 };    /* 例：读 ID 命令 + dummy 时钟 */
    u8 rx[4] = { 0 };
    struct spi_transfer t = {
        .tx_buf = tx,
        .rx_buf = rx,
        .len    = sizeof(tx),
    };
    struct spi_message m;
    int ret;

    spi_message_init(&m);
    spi_message_add_tail(&t, &m);
    ret = spi_sync(spi, &m);
    if (ret)
        return ret;
    *id = (rx[2] << 8) | rx[3];      /* 时序含义查芯片手册 */
    return 0;
}
```

SPI 是全双工：每个 transfer 收发等长，`tx_buf` 里的 0 就是"只发时钟不收数据"的占位。多段传输（如"先写命令再读数据"且中间不升 CS）用多个 `spi_transfer` 挂在同一条 `spi_message` 上。模式（CPOL/CPHA）通过 dts 的 `spi-cpol`、`spi-cpha` 或控制器默认值设置。

### 用户态对照：spidev

不想写内核驱动时，`spidev` 通用驱动把 SPI 直接暴露成 `/dev/spidevX.Y`：

```c
uint8_t tx[4] = { 0x9F, 0, 0, 0 }, rx[4];
struct spi_ioc_transfer tr = {
    .tx_buf        = (unsigned long)tx,
    .rx_buf        = (unsigned long)rx,
    .len           = 4,
    .speed_hz      = 1000000,
    .bits_per_word = 8,
};
ioctl(fd, SPI_IOC_MESSAGE(1), &tr);
```

dts 里把 compatible 写成 `spidev` 支持的条目（如 `rohm,dh2228fv`）即可。原型验证利器，但量产驱动应进内核——错误处理、并发、中断都没有的字符口不适合长期维护。

## regmap：收口的下一步

寄存器型芯片（动辄几十个寄存器）继续手写 `i2c_master_send` 会很快失控。`regmap` 框架把总线差异抹平：

```c
struct regmap_config cfg = { .reg_bits = 8, .val_bits = 8 };
struct regmap *map = devm_regmap_init_i2c(client, &cfg);
regmap_read(map, 0x01, &val);
regmap_update_bits(map, 0x02, MASK, val);
```

同一份寄存器代码换 SPI 芯片只需 `devm_regmap_init_spi`。写第二个总线驱动时值得引入。

## 常见陷阱

- **7 位 vs 8 位地址**：datasheet 常写"写地址 0x88、读地址 0x89"（含 R/W 位的 8 位制式），dts `reg` 和 `i2cdetect` 都用 7 位地址 `0x44`——右移一位即可，别直接把 0x88 写进 `reg`。
- **时钟延展**：SHT30 这类器件转换期间拉低 SCL 延展时钟，主机控制器必须支持（rockchip 控制器支持），超时表现为 `i2c_master_send` 返回 `-EBUSY`/`-ETIMEDOUT`。
- **上拉电阻缺失**：I2C 是开漏总线，模块没带上拉时整条总线读不出高电平，症状像"地址扫不到"。
- **SPI 模式错**：现象是读到全 0 或全 1，核对 CPOL/CPHA 与 dummy 字节数量；示波器看 CS 间隙和时钟数。
- **probe 里 `msleep` 太长**：影响启动速度，长延时自检可用 `usleep_range` 或推迟到首次访问。

## 检查清单

- 用户态 `i2cdetect`/`spidev` 验证在前，驱动调试在后。
- probe 自检（读 ID），失败路径明确报错。
- 传感器数据 CRC/校验落实，单位换算对照 datasheet 样例数据验证。
- `reg`/`cs-gpios`/`spi-max-frequency` 等总线必备属性不缺。

## 实验

1. SHT30 模块接 i2c1（SDA/SCL + 上拉 + 3.3V），`i2cdetect` 确认 0x44。
2. 加载上面的驱动，`cat /sys/bus/i2c/devices/1-0044/temperature` 验证读数，哈气观察变化。
3. 逻辑分析仪抓 I2C 波形：地址字节 ACK、测量命令、6 字节返回，与 datasheet 时序对照。
4. 进阶：把测量命令换成周期模式（0x20 0x32 等），用 `regmap` 重写寄存器访问。

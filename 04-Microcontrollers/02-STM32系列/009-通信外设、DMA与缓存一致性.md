# 通信外设、DMA 与缓存一致性

UART、SPI、I²C、CAN、USB 和 Ethernet 的协议规则由各自规范决定，STM32 章节主要处理外设实例、时钟、引脚、FIFO、DMA 请求和错误恢复怎样组合。

## 外设配置的共同问题

| 问题 | 需要确认 |
|---|---|
| 时钟 | 外设内核时钟来源、允许误差和切换行为 |
| 引脚 | AF 编号、电气类型、上拉、速度和板级连接 |
| 帧格式 | 位宽、极性、相位、停止位、采样点和端序 |
| 数据通路 | 轮询、中断、DMA、FIFO 阈值和缓冲区容量 |
| 错误 | 超时、溢出、仲裁、总线关闭、短帧和恢复顺序 |
| 并发 | 回调上下文、取消、重复启动和句柄所有权 |

协议电气和布线见 [[05-Communication/00-README|通信协议]]，本节不重复协议教程。

## 轮询、中断和 DMA 怎样选

- 短小、低频且启动阶段使用的数据可用带超时轮询；
- 不规则小事件适合中断和状态机；
- 连续或批量数据适合 DMA、环形缓冲和明确的背压；
- 极高数据率还要考虑 FIFO、总线仲裁、缓存和处理器消费能力。

选择依据是端到端期限、吞吐、能耗和错误恢复，不是“DMA 一定更快”。CPU 仍要配置 DMA、处理完成和错误、管理缓冲区，并消费数据。

## STM32 DMA 不是统一外设

不同系列可能使用通道、Stream、DMAMUX、GPDMA、LPDMA 或链表节点等模型。请求映射、可访问 RAM、突发、双缓冲和链表能力都不同。驱动代码应隔离这些平台差异，不在应用层固定 `DMA1_Channel1`。

```mermaid
flowchart LR
    A["应用填充或申请缓冲区"] --> B["驱动验证长度与状态"]
    B --> C["必要的缓存清理与屏障"]
    C --> D["DMA/外设拥有缓冲区"]
    D --> E["完成、错误或超时"]
    E --> F["必要的缓存失效与状态确认"]
    F --> G["缓冲区归还应用"]
```

## 缓存和 RAM 可达性

带 Cortex-M7 或其他缓存结构的器件上，DMA 与 CPU 可能看到不同数据。还可能存在 DMA 无法访问的 TCM 或特定 RAM 域。需要从总线矩阵、存储器映射和缓存策略确认：

- DMA 控制器能否到达该地址；
- 缓冲区是否按缓存行对齐并独占完整缓存行；
- 发送前执行正确的清理，接收交接执行正确的失效；
- 长度扩展到缓存行边界不会破坏邻接对象；
- 屏障、描述符和数据的顺序符合平台文档。

具体原理见 [[04-Microcontrollers/06-中断与DMA深入/003-Cache一致性|Cache 一致性]]。

## HAL 回调不是业务层入口

HAL 回调通常运行在中断上下文。回调应确认句柄和事件来源，更新短小状态或投递事件，不在其中使用 `printf`、`HAL_MAX_DELAY`、动态分配或无界解析。取消和超时还要确认外设及 DMA 是否真正停止，迟到回调不会操作已经复用的缓冲区。

UART 空闲线接收、SPI 全双工、I²C 状态机、CAN/FDCAN 消息 RAM 和 USB 端点都有专门边界，正式实现应依据对应系列 HAL 文档和参考手册，不从另一个系列复制句柄配置。

## 验证清单

- 最大数据率持续运行时不溢出，队列满策略可观测。
- 注入帧错误、总线断开、超时和重复启动，系统能恢复。
- DMA 缓冲区所有权在成功、错误、取消和复位路径都闭合。
- 发布优化下验证回调并发，不依赖调试日志改变时序。
- 带缓存平台测试对齐、跨缓存行和不同 RAM 区域。

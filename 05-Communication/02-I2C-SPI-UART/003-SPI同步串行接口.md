# SPI 同步串行接口

SPI（Serial Peripheral Interface，串行外设接口）用主机产生的时钟把数据一位一位地推过一条位移链路，没有地址、没有应答、没有超时重传。协议简单到可以在一页纸内讲完，这也正是它快的原因，同时也是它的全部风险所在：任何时序错误都不会被协议本身发现，只会表现为数据错位、全 0、全 0xFF 或者偶发误码。

## 1. 信号线作用

| 信号 | 方向 | 作用 |
|---|---|---|
| SCK | 主机 → 从机 | 串行时钟，完全由主机产生；从机无法拉伸或暂停 |
| MOSI | 主机 → 从机 | 主机移出、从机移入，名称亦作 SDI、DIN、SI |
| MISO | 从机 → 主机 | 从机移出、主机移入，名称亦作 SDO、DO、SO |
| CS/SS/NSS | 主机 → 从机 | 片选，低电平有效（少数器件高有效），每个从机一根 |

四线是单从机的最小配置。多一个从机就多一根 CS，这是 SPI 引脚数的线性代价，也是它无法像 I²C 那样"两根线挂十个器件"的原因。有些器件把 MISO 复用为数据就绪或中断输出，读取前需要先查数据手册确认该引脚在何种命令下有效。

## 2. 主从移位寄存器模型

SPI 的本质是主机和从机各有一个移位寄存器，由 CS 选中后二者的寄存器被串成一个环：主机每移出一位到 MOSI，就从 MISO 移入一位；从机同时移出一位并移入一位。因此收发是同一个物理过程，不存在"只发送"或"只接收"的操作。

这个模型解释了几个实际现象。其一，主机发送 N 字节必然接收 N 字节，读寄存器操作通常需要"发地址、收数据"两个阶段，第一次发送的字节往往是哑字节，其内容无关紧要。其二，从机在 CS 有效期间输出的内容取决于它内部的状态机：很多器件在前一个字节（通常是指令字节）被移入后才开始驱动 MISO，因此第一个返回字节可能是无效数据。其三，从机没有时钟拉伸能力，主机必须按从机数据手册规定的最大时钟频率配置 SCK，并在从机数据未就绪时靠延时或状态引脚等待。

## 3. CPOL/CPHA 四模式

CPOL 定义 SCK 空闲时的电平，CPHA 定义数据在哪个边沿移出、哪个边沿采样：

| 模式 | CPOL | CPHA | SCK 空闲电平 | 移出沿 | 采样沿 |
|---|---|---|---|---|---|
| Mode 0 | 0 | 0 | 低 | 下降沿 | 上升沿 |
| Mode 1 | 0 | 1 | 低 | 上升沿 | 下降沿 |
| Mode 2 | 1 | 0 | 高 | 上升沿 | 下降沿 |
| Mode 3 | 1 | 1 | 高 | 下降沿 | 上升沿 |

记忆方式：CPOL 决定空闲电平，CPHA=0 表示在第一个边沿就采样（数据必须在 CS 有效后、第一个边沿前就准备好），CPHA=1 表示在第二个边沿采样（第一个边沿先移出）。主从模式不匹配是最常见的 SPI 故障：症状通常是读到固定的 0x00 或 0xFF，或者数据里出现规律性的位错位。先查从机数据手册标注的模式，再改主机配置，不要靠试四种组合来碰运气——试出来的结果可能只是恰好能读到一个寄存器。

## 4. 时序参数与最高 SCK

从机数据手册会给出以采样沿为基准的几组时间参数，含义如下：

- 数据建立时间：从机输出（或要求主机输入）的数据必须在采样沿之前保持稳定的最短时间；
- 数据保持时间：采样沿之后数据仍需保持稳定的最短时间；
- CS 建立与保持时间：CS 有效到第一个时钟沿之间的最短间隔，以及最后一个时钟沿到 CS 释放之间的最短间隔；
- CS 高电平最短时间：两次传输之间的最小间隔，很多器件需要这段时间完成内部状态复位。

主机能用的最高 SCK 受这些参数共同限制：把从机的建立时间与保持时间、主机输出的延迟差异、PCB 走线偏斜和主从时钟抖动都算进去，得到的是"整个环路上最坏情况下数据仍能被正确采样"的周期。粗略的判据是：

$$
T_{SCK} > t_{su} + t_{hd} + t_{skew}
$$

如果数据手册只给了 `t_su` 和 `t_hd`，就按上式留出至少 20%~50% 的裕量。串行 Flash 常见几十 MHz，SD 卡在默认模式下只有约 25 MHz，高速模式下可更高，各类传感器通常在 1~20 MHz 区间，具体数值以数据手册为准；需要核对的项是"Maximum SCK Frequency"、"Data Setup Time"、"Data Hold Time" 和 "CS Setup/Hold Time"。

## 5. 多从机片选方案与菊花链

独立片选是最常用的方案：所有从机共享 SCK/MOSI/MISO，每个从机一根独立 CS，主机一次只拉低一个。要点是未被选中的从机必须把 MISO 置为高阻，否则会出现多个器件同时驱动 MISO 的冲突；若某个器件的 MISO 无法进入高阻，就需要在该线上串一只电阻或在外部加缓冲器。上电初始化阶段经常忘记给所有 CS 置为无效电平，导致从机在上电瞬间收到伪时钟或误判指令。

菊花链适用于支持该结构的器件（典型是级联的移位寄存器与部分驱动芯片）：主机只发一根 CS，把所有从机的数据串成一个位移链，一次传输把所有数据推过去。它节省引脚，但任何一个器件不支持菊花链或者链路中某个器件失效都会破坏整条通路，且访问第 k 个器件需要发送前面所有器件的字节。判断某颗器件是否支持，要看数据手册里是否有 "Daisy-chain" 或 "cascade" 的说明。

## 6. 高速下的信号完整性

SPI 的 SCK 是方波，频率越高，越容易在劣质布线上出现振铃、串扰和地弹。常见措施：

- 缩短走线并让 SCK 与数据线尽量并行走在同一层，避免大环路；
- 在 SCK 源端串联一只几十欧姆的电阻做源端匹配，减小过冲；
- 每根信号线附近有完整地回流路径，不要在参考平面上开槽；
- 高速走线避免跨越分割地平面，分支线尽量短；
- 探头与排线本身有几十 pF 的寄生电容，调试时接上逻辑分析仪可能让原本正常的边沿变慢。

测量时要注意探头负载的影响：用示波器看 SCK 波形时，探头电容会加重上升沿变缓，判断"是不是信号质量问题"要在同一测量条件下与从机数据手册的时序门限比较，而不是与示波器上看到的"方波程度"比较。信号完整性的系统方法见 [[06-PCB-Design/02-信号完整性基础/002-高速信号基础|高速信号基础]]。

## 7. 常用器件类别

| 器件类别 | 典型接口特征 | 使用要点 |
|---|---|---|
| NOR/NAND Flash | 指令 + 地址 + 数据多阶段传输 | 需要先发指令字节；DMA 用于大块读写 |
| SD 卡 | 命令/响应双向 | 默认速率较低，高速模式需先完成握手与配置 |
| TFT LCD、OLED | 单向写为主 | 用 DMA 批量推像素；注意 DC 之类的辅助信号 |
| 高速 ADC、IMU | 固定帧长，MSB first | 关注转换完成标志与 MISO 有效时刻 |
| 无线模块（nRF24L01、LoRa） | 寄存器读写 + FIFO 多字节传输 | 区分寄存器操作与突发读写命令 |
| 数字电位器、IO 扩展 | 低速，链路简单 | 常支持菊花链 |

## 8. 常见故障

| 现象 | 常见原因 | 定位手段 |
|---|---|---|
| 模式不匹配 | CPOL/CPHA 与从机不符 | 逐个核对数据手册标注的模式与主机配置 |
| 读回恒为 0xFF | MISO 未连接或未被驱动；从机未被选中 | 只测 MISO 一个字节，观察是否有任何跳变 |
| 读回恒为 0x00 | 从机未上电、被复位、CS 未生效 | 测 CS 与 VDD；确认 CS 极性 |
| CS 时序过短 | 两次传输间隔小于器件要求 | 加密 CS 高电平时间；核对 CS 建立/保持要求 |
| 时钟过高导致数据错位 | 超过从机最大 SCK | 降频重试；核对建立/保持时间 |
| 长线振铃、误码率高 | 无源端匹配、走线过长、地回流差 | 串联电阻；缩短走线；检查参考平面 |
| 多从机 CS 串扰 | 某个从机未被选中时仍驱动 MISO | 检查 MISO 高阻条件；加缓冲或串联电阻 |
| 只读到无效首字节 | 从机在指令字节移入后才驱动 MISO | 忽略首字节；按数据手册的时序图确定有效位置 |
| 长时间运行偶发错位 | 主从时钟偏斜、温漂、供电噪声 | 降频验证；检查去耦与地弹 |

调试时优先确认三件事：CS 是否在传输期间保持有效、SCK 是否真的在跳、MISO 在采样沿是否稳定。这三项成立之后，剩下的问题基本都能从模式与字节顺序上找到。I²C 与 SPI 的电气差异见 [[05-Communication/02-I2C-SPI-UART/004-I2C总线与多设备仲裁|I2C 总线与多设备仲裁]]，工具用法见 [[05-Communication/02-I2C-SPI-UART/005-总线设计与调试实践|总线设计与调试实践]]。

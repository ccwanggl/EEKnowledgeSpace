# 数字通信基础与选型

讨论 UART、SPI、I²C 之前需要先分开三件常被混为一谈的事：电气层决定电平如何表达 0 和 1、由谁驱动这根线、走多远还能被正确识别；链路层决定一串比特如何切分成帧、靠什么对齐收发双方的节拍；拓扑层决定谁有权在什么时刻说话。同一组帧规则换一个电气层，可靠性、距离和抗干扰能力会变化几个数量级——UART 的帧格式在 TTL、RS-232 和 RS-485 上完全一致，但可用距离从不到 2 m 变成约 1200 m。

## 1. 单端与差分

单端信号以地为参考，接收端比较信号线与本地地的电位差。它省线、省收发器，但发送端地与接收端地之间的电位差会直接叠加到判决门限上，长线耦合进来的共模噪声也照样进入比较器。板内几厘米到几十厘米、双方共地的场合，单端足够。

差分信号用一对线，接收端取两者之差。共模噪声同时抬高两条线，相减后被抵消；地电位差同样主要落在共模上。代价是线数翻倍、需要差分收发器和终端匹配。用一条经验判据：当信号往返传播时间与上升时间可比时，单端走线就开始出现反射与串扰问题，此时应改用差分或者收短线长。

## 2. 推挽输出与开漏输出

推挽输出的引脚内部有上拉和下拉两个器件，高电平和低电平都由驱动级主动产生，边沿快、驱动能力强，适合单向、点对点、速率较高的信号，例如 SPI 的 SCK/MOSI 与 UART 的 TX。

开漏输出只有下拉器件，引脚只能主动拉低，高电平完全依赖外部上拉电阻。它的关键性质是可以把多个器件的输出直接连在一根线上：只要有一个器件拉低，线就是低；全部释放，线才被上拉拉高。这正是 I²C 能实现多主仲裁和 ACK 应答的电气基础，也意味着上升沿永远是 RC 充电过程，上升时间 `t_r ≈ 0.847·R·C` 直接限制最高速率，计算见 [[05-Communication/02-I2C-SPI-UART/004-I2C总线与多设备仲裁|I²C 总线与多设备仲裁]]。

## 3. 上拉、上升时间与终端匹配

上拉电阻把一个开漏网络从低电平恢复到高电平，需要给全部总线电容充电。总线电容包括 PCB 走线、器件引脚、连接器与排线，典型量级从几十 pF 到 400 pF。电阻越大越省电、灌电流越小，但上升越慢；电阻越小边沿越快，但低电平被拉高、功耗增加。

高速单端与差分链路还要处理反射：当线长足以让信号在传播过程中"看到"阻抗突变（分支、连接器、开路末端），返回的反射波会叠加成过冲与振铃。抑制手段是让驱动端阻抗与走线阻抗接近（常见做法是串联一只几十欧姆的电阻做源端匹配）并在总线两端加终端匹配，例如 RS-485 的两端各一只 120 Ω。具体的线长阈值、阻抗取值和叠层安排属于 PCB 设计范畴，见 [[06-PCB-Design/03-PCB层叠与阻抗设计/003-受控阻抗|受控阻抗]]。

## 4. 共模与地电位差

两块电路板各自接地时，两个"地"之间可能存在开关电源纹波、电机电流在地线上产生的压降或者静电泄放造成的瞬时电位差。单端接口把这段压差当作信号的一部分，超过门限就误码；差分接口把它当作共模。缺乏共地时，即使两侧电平看起来都正常，UART 也可能间歇性收到乱码，这是现场最常见的接线错误之一，排查方法与 [[05-Communication/02-I2C-SPI-UART/002-UART异步串行通信|UART 异步串行通信]]中的共地缺失条目对应。

## 5. 同步与异步

异步通信不传时钟，接收端靠帧内的起始位重新对齐节拍。UART 就是这样：空闲为高，出现下降沿即进入起始位，接收端在自己的时钟节拍上对每一位采样。这要求双方对"一位有多长"有共识，也就是波特率必须匹配，且误差在整帧长度内不能累积到采样点跌出位窗口。

同步通信由主机显式发送时钟，从机在时钟边沿采样。SPI 的 SCK 与 I²C 的 SCL 都属于这一类，因此不存在波特率误差累积问题，只存在时序参数问题：数据必须在采样沿之前建立、之后保持足够时间。代价是必须多一根时钟线，且距离越长时钟与数据之间的偏斜越大。

## 6. 单工、半双工与全双工

单工指数据只能单向流动，例如只发送的传感器；半双工指一条通道分时双向，同一时刻只能有一个方向有效，I²C 的 SDA 与 RS-485 的差分对都属于此类，方向切换需要软件或硬件控制，并由收发器使能引脚的切换延时决定切换开销；全双工指两个方向各有独立通道，可以同时收发，UART 的 TX/RX 与 SPI 的 MOSI/MISO 都是全双工。

SPI 的全双工常被误解。它确实是同时收发，但本质是主从两个移位寄存器串联成环：主机每移出一位就必然移入一位，因此"只读"操作通常也要发送一个哑字节，读到什么取决于从机在对应时钟周期输出什么，详见 [[05-Communication/02-I2C-SPI-UART/003-SPI同步串行接口|SPI 同步串行接口]]。

## 7. 主从与多主

主从结构中只有主机产生时钟并发起传输，从机被动应答。SPI 是典型的一主多从；UART 名义上点对点，但双方地位对等，谁都能随时发送。

多主结构允许总线上存在多个可以发起传输的主机，需要一套仲裁机制决定谁赢。I²C 用开漏线与逻辑实现逐位仲裁：所有主机同时发送地址，每一位发出后回读总线，若自己发 1 而读到 0，说明有别的设备发 0，立即退出并转为接收。仲裁不会破坏获胜方的数据，也不需要额外的仲裁线，代价是速率受限于开漏上升时间。

## 8. 位序、编码与时钟恢复

位序规定一个字节里哪一位先上线。UART 与 SPI（多数配置）都是 LSB first，I²C 是 MSB first。位序配置错误时，收到的数据会呈现规律性的位反转，例如 `0x01` 变成 `0x80`，这是快速定位位序问题的特征现象。

编码方式决定 0 和 1 怎样映射到电平，并影响接收端能否从数据流里恢复时钟。NRZ（不归零）用恒定电平表示一位，效率最高但没有内建跳变，长串相同位会让接收端失去节拍参考，因此常配合位填充：编码器在连续若干个相同位之后强制插入一个相反位，接收端再把它去掉。UART 每帧只有 10 位左右且以起始位重新同步，所以不需要位填充；I²C 与 SPI 靠独立时钟线，同样不需要。更复杂的编码（曼彻斯特、8b/10b 之类）用跳变换直流平衡与时钟恢复能力，在 UART/SPI/I²C 中不作为常规选项，具体线编码以所选器件的数据手册为准。

## 9. 选型因素

| 因素 | 需要问的问题 | 影响的方向 |
|---|---|---|
| 数据量 | 峰值与平均吞吐率各是多少 | 大块数据与高刷新率倾向 SPI |
| 实时性 | 允许的最大延迟与抖动 | 需要确定时延的场合避免软件模拟与阻塞式收发 |
| 引脚预算 | MCU 还剩几个可用引脚 | 从机多则 I²C 的两线优势明显 |
| 从机数量 | 是否需要动态增减节点 | 片选方案随从机数线性消耗引脚 |
| 距离 | 板内、板间还是机柜之间 | 超过板内范围考虑差分与独立物理层 |
| 电磁环境 | 附近是否有电机、开关电源、继电器 | 决定是否需要差分、屏蔽与滤波 |
| 供电与电平 | 两侧 IO 电压是否一致 | 不一致需要电平转换或耐压开漏 |
| 热插拔 | 是否允许运行中插拔 | I²C 与 SPI 都不天然支持 |
| 已有生态 | 器件是否只提供某一种接口 | 通常由器件决定而非由设计者决定 |
| 调试成本 | 能否用现成工具解码 | 三者在逻辑分析仪上都有成熟解码器 |

实际项目中，器件选型往往先定接口，再由接口反过来约束 MCU 与 PCB，把顺序搞反会导致大量软件模拟或电平转换电路。

## 10. 常用参数速查

| 项目 | UART（TTL） | SPI | I²C |
|---|---|---|---|
| 速率范围 | 9600 ~ 921600 bps 常见，更高需核对外设能力 | 常见 1 ~ 50 MHz，具体上限由从机时序与 PCB 决定 | 100 kHz / 400 kHz / 1 MHz / 3.4 MHz |
| 距离量级 | 板上 < 2 m | 板内数厘米至数十厘米 | 板内，受总线电容与上拉限制 |
| 线数 | 2 + GND | 3 + 每从机 1 根 CS + GND | 2 + GND + 上拉 |
| 拓扑 | 点对点（配合收发器可组多点总线） | 一主多从 | 多主多从 |
| 时钟 | 无，靠起始位同步 | SCK，主机产生 | SCL，主机产生并可被从机拉伸 |
| 电气基础 | 推挽 | 推挽 | 开漏 + 上拉 |
| 上行错误检测 | 校验位、帧错误 | 无，靠协议层 | ACK/NACK、总线错误、仲裁丢失 |

速率上限只是起点。真正决定能否跑通的往往是器件的建立与保持时间、总线电容、走线长度与探头负载，这些内容分别在三篇单协议笔记中展开。

# 描述符与枚举过程

描述符是设备交给主机的自述材料，枚举是主机按固定顺序把这些材料读全并据此加载驱动的过程。设备侧几乎所有"插上没反应"的问题，都能归结到某个描述符字段写错、某次控制传输没有正确应答，或设备在还未被配置时就试图使用端点。本篇按字段和组织顺序展开，并把每一步枚举对应的标准请求写清楚。

## 1. 描述符的层级与组织方式

标准描述符是嵌套结构：设备描述符描述整个设备，配置描述符下挂若干接口描述符，每个接口描述符下挂该接口的端点描述符集合。主机不依赖设备一次性给出所有内容，而是靠每个描述符头部的 `bLength` 找到下一个描述符的起点，用配置描述符的 `wTotalLength` 知道整个集合有多长。

描述符类型由 `bDescriptorType` 区分：1 为设备、2 为配置、3 为字符串、4 为接口、5 为端点。类特定描述符在同一层级里插入，例如 CDC 的功能描述符（类型 0x24）、HID 描述符（0x21）与 HID 报表描述符（0x22），它们的 `bDescriptorType` 落在 0x21～0xFF 区间，主机只有在匹配到对应接口类时才解析。因此读配置描述符集合时不能假设"接口描述符后面一定紧跟端点描述符"。

同一个接口可以有多个备用设置（alternate setting），用 `bAlternateSetting` 区分，常见于 UVC 的不同分辨率/带宽档位。同一时刻每个接口只有一个备用设置生效，切换通过 SET_INTERFACE 请求完成。备用设置必须在配置描述符集合里全部给出，缺少备用设置的接口在带宽协商时会失败。

## 2. 设备描述符关键字段

| 字段 | 长度 | 工程含义 |
|---|---|---|
| `bLength` | 1 B | 设备描述符固定 18 字节 |
| `bcdUSB` | 2 B | 设备支持的 USB 版本，BCD 编码如 0x0200 表示 2.0、0x0300 表示 3.x，影响主机对该设备可用特性与速率的判断 |
| `bDeviceClass` | 1 B | 0x00 表示类定义在接口层；0xFF 为厂商自定义；非零时该值适用于整个设备 |
| `bDeviceSubClass` | 1 B | 配合 `bDeviceClass` 使用，类在接口层时通常写 0 |
| `bDeviceProtocol` | 1 B | 同上，类在接口层时通常写 0 |
| `bMaxPacketSize0` | 1 B | 端点 0 单包上限，只能是 8/16/32/64，取值错误会让后续所有控制传输分帧失配 |
| `idVendor` / `idProduct` | 2 B + 2 B | 由 USB-IF 分配的 VID 与厂商自定的 PID，是主机匹配驱动的第一依据 |
| `bcdDevice` | 2 B | 设备版本号，用于区分同一 PID 的不同硬件/固件版本 |
| `iManufacturer` / `iProduct` / `iSerialNumber` | 各 1 B | 字符串描述符索引，0 表示该字符串不存在 |
| `bNumConfigurations` | 1 B | 配置数量；只给一个配置时写 1，多配置设备需要驱动侧配合切换 |

`idVendor` 不能随意填写，未注册的 VID 与已分配厂商冲突会导致驱动匹配到错误驱动或系统直接拒绝加载；量产设备应通过 USB-IF 申请 VID。`bcdUSB` 声明得比实际能力高（例如只实现 USB 2.0 却写 3.0）不会带来好处，只会让主机尝试高速链路协商并失败。

## 3. 配置、接口与端点描述符关键字段

配置描述符（9 字节）的 `wTotalLength` 是整个集合的总长度，包含它自己以及其下所有接口、端点、类特定描述符；`bNumInterfaces` 是接口数量；`bConfigurationValue` 是 SET_CONFIGURATION 使用的取值，必须与设备固件接受的值一致；`bmAttributes` 的最高位表示是否自供电，次高位表示是否支持远程唤醒；`bMaxPower` 以 2 mA 为单位，例如 0x32 表示 100 mA。

接口描述符的 `bInterfaceNumber` 是接口编号，`bInterfaceClass`、`bInterfaceSubClass`、`bInterfaceProtocol` 决定主机加载哪个类驱动。这三个值的组合有标准定义，例如 0x03/0x01/0x01 表示 HID 键盘、0x03/0x01/0x02 表示 HID 鼠标、0x08/0x06/0x50 表示 MSC 的 SCSI 透明命令集、0x02/0x02/0x01 表示 CDC-ACM。取值必须与实现的协议一致，否则系统会加载驱动后立刻报错。`iInterface` 是接口名字符串索引。

端点描述符（7 字节）的 `bEndpointAddress` 最高位表示方向：0x80 置位为 IN（设备到主机），清零为 OUT（主机到设备），低 4 位是端点号；`bmAttributes` 的低 2 位是传输类型（0 控制、1 等时、2 批量、3 中断），高位在等时传输里表示同步类型与用途；`wMaxPacketSize` 是单包上限，高速高带宽中断/等时端点还用高 2 位表示每微帧的额外事务数；`bInterval` 对中断和等时端点表示轮询周期，全速以帧（1 ms）为单位、高速以微帧（125 µs）为单位，其含义在高速下按 2 的幂次解释，确切规则以 USB 2.0 规范第 9 章为准。

## 4. 字符串描述符与语言 ID

字符串描述符以 UTF-16LE 编码，`bLength` 与 `bDescriptorType` 之后是 Unicode 字符。所有字符串共用一个语言 ID 数组，索引 0 指向它，数组元素是 LANGID（例如 0x0409 表示美式英语、0x0804 表示简体中文）。主机依次请求索引 0 与所需语言的字符串，设备若只支持一种语言就只返回一个 LANGID。

`iSerialNumber` 在多设备区分、绑定固定 COM 口或做设备白名单时很关键；如果产品没有唯一序列号，就把它写成 0，而不是返回一个所有设备都相同的常量。Windows 会用序列号参与设备实例路径的生成，序列号相同或缺失会让多个同类设备共用一个驱动实例与配置。

## 5. 控制传输与标准请求

端点 0 上的控制传输由三个阶段组成：SETUP 阶段主机发出 8 字节请求，DATA 阶段按请求方向传数据（可为零长度），STATUS 阶段方向反转以确认结果。SETUP 包的字段是 `bmRequestType`、`bRequest`、`wValue`、`wIndex`、`wLength`。`bmRequestType` 的最高位表示数据阶段方向（0 为 OUT、1 为 IN），第 6～5 位表示请求类型（0 标准、1 类、2 厂商），低 5 位是接收方（0 设备、1 接口、2 端点、3 其他）。

枚举用到的标准请求：

| 请求 | bRequest | 用途与关键字段 |
|---|---|---|
| GET_DESCRIPTOR | 0x06 | `wValue` 高字节为描述符类型、低字节为索引，`wLength` 为期望长度 |
| SET_ADDRESS | 0x05 | `wValue` 低字节为新地址，无数据阶段；设备在状态阶段完成后才切换地址 |
| GET_CONFIGURATION | 0x08 | 读回当前配置值 |
| SET_CONFIGURATION | 0x09 | `wValue` 低字节为 `bConfigurationValue`，成功后端点才可用 |
| GET_STATUS | 0x00 | 读设备/接口/端点的状态位（自供电、远程唤醒、Halt） |
| SET_FEATURE / CLEAR_FEATURE | 0x03 / 0x01 | 设置或清除远程唤醒、端点 Halt 等特性 |
| SET_INTERFACE | 0x0B | 切换接口的备用设置 |
| GET_INTERFACE | 0x0A | 读回当前备用设置 |

## 6. 枚举九步与每步的请求

1. 插入与端口检测：主机通过 D+/D- 上拉（见 [[05-Communication/05-USB协议/001-USB版本与物理层|USB 版本与物理层]]）发现设备，给端口供电并等待电源稳定。
2. 总线复位：主机驱动 SE0 至少 10 ms，设备进入默认状态，地址回到 0，端点 0 可用。
3. 读设备描述符前 8 字节：GET_DESCRIPTOR（设备，`wValue`=0x0100，`wLength`=8）。此步只为拿到 `bMaxPacketSize0`，之后的数据阶段才可能按该尺寸分帧。设备必须能在被分配地址之前响应，且要容忍主机只读 8 字节。
4. 设置地址：SET_ADDRESS（`wValue`=新地址），无数据阶段，设备在状态阶段结束后使用新地址。
5. 用新地址读完整设备描述符：GET_DESCRIPTOR（`wValue`=0x0100，`wLength`=18），确认地址切换成功并取得全部字段。
6. 读配置描述符集合：先 GET_DESCRIPTOR（`wValue`=0x0200，`wLength`=9）拿 `wTotalLength`，再按该长度（或分批）读完整集合，取得接口、端点与类特定描述符。
7. 读字符串描述符：先取索引 0 的语言 ID 数组，再按需读取 `iManufacturer`、`iProduct`、`iSerialNumber` 等。这一步是可选的，失败通常不会阻断枚举，但会影响设备显示名称。
8. 设置配置：SET_CONFIGURATION（`wValue`=所选 `bConfigurationValue`）。成功后非 0 端点才允许传输，`bMaxPower` 声明的电流才生效。
9. 驱动匹配：主机侧堆栈按 VID/PID、设备类与接口类/子类/协议加载驱动并创建设备节点；匹配失败表现为"未知 USB 设备"或仅有设备名而无功能驱动。

## 7. 接口与端点的编址规则

接口编号从 0 开始连续，端点号在每个接口内独立编号，不同接口可以使用相同端点号而不冲突。端点 0 是所有设备必须实现的默认控制端点，它不属于任何接口，方向由每次传输本身决定，因此不存在 `bEndpointAddress` 为 0x00 或 0x80 的端点描述符。

按惯例，IN 端点常用偶数编号之外的奇数或成对分配，例如一个 CDC 接口用 0x81（IN，中断通知）与 0x01（OUT，批量数据），另一个接口用 0x82 与 0x02。这属于约定而非规范强制，但遵循它能减少驱动兼容性问题。同一接口内两个端点使用相同方向相同编号（例如两个 0x81）会直接导致配置描述符无效。

## 8. 常见枚举失败原因

描述符长度不符是最常见的一类：`bLength` 与实际长度不一致会让主机错位读取后续描述符，表现为枚举中途停止或读到乱码 `bDescriptorType`。配置描述符集合不完整同样致命——`wTotalLength` 报了 32 字节但实际只发了 25 字节，或集合里漏掉了某个接口的端点描述符，主机可能只识别出部分接口，或加载驱动后提示找不到端点。

控制传输 STALL 与握手错误方面：设备对未实现的标准请求应回 STALL，但对枚举必需请求必须正确应答；如果设备在 SET_ADDRESS 状态阶段之前就切换地址，主机后续请求会打到旧地址导致超时；如果设备在 DATA 阶段返回的字节数少于 `wLength` 但没有正确终止，主机可能一直等待。

供电与电气方面：总线供电设备申报 `bMaxPower` 超过端口能力时配置请求被拒绝，或 VBUS 在枚举中被拉低导致设备反复重连；线缆过长、差分对阻抗不连续、缺少 ESD 保护造成的信号劣化通常表现为"能识别但反复枚举"。

时序与主机策略方面：部分主机控制器对枚举各步有超时限制，固件在描述符请求里做慢速闪存读或阻塞式操作会超时；Windows 会缓存设备配置，改了 PID/VID 后仍复用旧驱动记录，需要卸载设备或清理驱动缓存才会生效。HID 报表描述符语法错误不会阻止枚举，但会让 Windows 报"设备无法启动（代码 10）"，排查方法见 [[05-Communication/05-USB协议/003-传输类型、端点与设备类|传输类型、端点与设备类]] 与 [[05-Communication/05-USB协议/004-嵌入式USB实现与调试|嵌入式 USB 实现与调试]]。

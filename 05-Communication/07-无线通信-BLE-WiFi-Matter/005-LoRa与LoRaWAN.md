# LoRa 与 LoRaWAN

LoRa 用扩频换灵敏度和距离，LoRaWAN 用"终端不管网关、网关转发给网络服务器"的星型架构换部署成本。两者的分工必须分清：LoRa 是 Semtech 的物理层调制技术，LoRaWAN 是 LoRa Alliance 维护的 MAC 与网络层规范。同样用 LoRa 调制的私有协议完全可以在没有网络服务器的情况下点对点通信，这也是很多行业应用的取舍点。

原笔记给出的量级适合建立直觉：城市环境 2~5km、农村 10~15km，速率 0.3~50kbps，Sub-GHz 频段（433/868/915MHz）。这些数字的具体落点完全由扩频因子、带宽和发射功率决定，下面给出可复算的关系。

## 1. Chirp Spread Spectrum 的直观解释

LoRa 在每个符号周期内让载波频率线性扫过一段带宽，这就是 chirp（啁啾）。接收端用一个频率变化方向相反的本地 chirp 与接收信号做相关，原本散布在整个带宽上的能量被压缩成一个窄峰，峰值位置对应符号值。这是扩频增益的来源：信号能量没变，但噪声被摊到整个带宽上，而有用信号集中到一点。

关键参数有三个。扩频因子 SF 决定每个符号携带的比特数，$SF$ 越大，符号数越多、单符号持续时间越长、抗噪能力越强，速率越低。带宽 BW 决定 chirp 扫过的频率范围，值越大则单符号时间越短、速率越高，但噪声带宽增加、灵敏度变差。编码率 CR 是前向纠错的开销比例，$4/5$ 表示每 4 个信息比特附加 1 个纠错比特，$CR$ 越保守（如 $4/8$）抗突发错误能力越强、有效载荷越小。

符号持续时间与等效速率的关系为：

$$
T_s = \frac{2^{SF}}{BW}, \qquad R_b \approx SF \cdot \frac{BW}{2^{SF}} \cdot CR
$$

代入 $SF=12$、$BW=125\mathrm{kHz}$，单符号时间约 32.8ms，等效比特率约 293bps（未计编码开销）；$SF=7$、$BW=125\mathrm{kHz}$ 时单符号时间约 1.02ms，等效比特率约 5.5kbps，乘 $4/5$ 编码率后仍在 4kbps 量级。原笔记"0.3~50kbps"的下限对应最高 SF 与最小带宽，上限对应最低 SF 与最宽带宽组合。这只是量级估算，精确数值请用 Semtech 的空中时间计算器或数据手册公式核对。

## 2. 空口时间估算与占空比约束

空中时间等于前导、报头与载荷符号时间之和，近似为：

$$
T_{air} \approx T_{preamble} + T_{header} + \frac{8 \cdot PL}{R_b}
$$

其中 $PL$ 为载荷字节数。以 $SF=12$、$BW=125\mathrm{kHz}$、$PL=20$ 字节估算，$T_{air}$ 在 1~2 秒量级；同参数下 $SF=7$ 则只需几十毫秒。这就是 LoRa 设计的核心矛盾：SF 每提高一档，灵敏度改善约 2.5dB，但空中时间和耗电近乎翻倍。

占空比约束会直接限制上报频率。若所在子带限 1% 占空比，空中时间 1.5s 的报文每天最多只能发送约 576 次（86400×1%/1.5），换算下来约每 2.5 分钟一次；若空中时间降到 100ms，同样的占空比允许每 10 秒一次。因此"LoRa 速率低没关系，反正传感器数据少"这个说法只在占空比允许的范围内成立。

## 3. Sub-GHz 频段与中国频段

LoRaWAN 的区域参数把频段、信道计划、发射功率和数据速率组合成地区配置文件：EU868、US915、AS923、AU915、IN865 等，每个区域对信道、功率和占空比的规定不同，设备必须按目标区域配置且不可混用。原笔记列出的 CN470/779 对应中国的两个常用区间：470~510MHz 是较早开放、使用较广的计量类频段，779~787MHz 面向低功率广域物联网，两者的信道计划、功率限值与是否强制占空比均以现行法规和 LoRaWAN 区域参数为准。

跨区域部署时最容易踩的坑是"用 EU868 的参数在中国发射"：频段不同、许可不同，产品无法通过型号核准，也无法合法使用。

## 4. 网络架构

LoRaWAN 是星型拓扑：终端以单跳方式把数据发给一个或多个网关，网关把报文原样转发到网络服务器，网络服务器负责去重、鉴权、MAC 命令处理和路由，再交给应用服务器。终端不绑定某个网关，同一报文被多个网关收到时由网络服务器去重，这带来覆盖冗余但也意味着下行必须由网络服务器选择合适的网关下发。

网关通常是 Linux 平台加多通道基带芯片（SX1301/2/3 一类），可同时监听多个信道和多种数据速率，因此单网关能容纳不同 SF 的终端。终端与网关之间的链路质量只看这一跳，网络服务器的去重与下行调度逻辑是部署中需要理解的部分。

## 5. Class A/B/C 的接收窗口与取舍

Class A 是所有 LoRaWAN 设备都必须支持的最低要求：终端每次上行结束后打开两个短暂的接收窗口（常见延时为 1s 与 2s，具体由区域参数规定），窗口之外完全不休眠监听。它的功耗最低、下行延迟最大，适合以终端主动上报为主的应用。

Class B 在 Class A 之上增加周期性同步接收窗口，靠网关广播的信标对齐时间，使网络服务器可以在约定时刻下发。功耗居中，下行延迟从"等下次上报"缩短到信标周期的量级，代价是终端需要保持时间同步、定期接收信标，平均电流上升。

Class C 几乎持续保持接收窗口（仅在上行时短暂关闭），下行延迟最低、功耗最高，通常需要市电供电。原笔记把 Class C 描述为"最高延迟"是不准确的：Class C 的下行延迟最小，功耗最大，这两项取舍恰好与 Class A 相反。

## 6. 入网方式：OTAA 与 ABP

OTAA（Over-The-Air Activation）在入网时执行 Join 流程，双方用 AppKey 派生出会话密钥，网络服务器分配 DevAddr 并建立会话上下文。会话密钥可以周期更新，设备被复制或密钥泄露的风险较低，代价是入网需要多次空口交互、失败时需要重试。

ABP（Activation By Personalization）把 DevAddr 和会话密钥直接烧进设备，设备开机即可发送、无需 Join 流程。它的代价是会话密钥长期固定、帧计数器管理容易出问题（服务器侧若对帧计数器做重放检查，设备复位后计数器回退会导致全部上行被丢弃），因此 ABP 更适合调试或密钥管理可控的封闭部署。

帧计数器与重放保护是 OTAA/ABP 之外的另一个常见坑：设备重启后计数器是否持久化、网络服务器是否允许计数器回退，都需要在联调阶段确认。

## 7. ADR、占空比与下行限额

自适应数据速率（ADR）让网络服务器根据终端上报的链路质量指示，命令终端调整 SF、带宽和发射功率：链路好时提高速率以缩短空中时间，链路差时降低速率以保覆盖。ADR 适合固定安装、射频环境稳定的终端；移动终端或链路快速变化的场景应关闭 ADR 或使用较保守的速率。

区域参数还会限制网络的下行总量（例如按每天或每个上行对应的下行配额）与占空比。这意味着下行命令不能随意发送，产品设计应把配置下发设计成"终端主动请求"而非"服务器随时推送"，否则会撞上配额限制。

## 8. 网关容量与并发

网关容量由基带芯片能同时解调的信道数与数据速率组合决定。极端情况下大量终端使用同一个 SF 在同一信道上发送会互相碰撞，需要靠信道计划和 SF 分布把负载摊开。估算容量时要同时考虑：区域内可用信道数、每个信道能同时解调的 SF 数、单包空中时间，以及占空比允许的总发射时间。

实践中的经验是给每个信道留出充分的碰撞余量，并优先让近端终端使用高数据速率以缩短占空比占用，"把速率降下来更保险"反而会拖垮网络容量。

## 9. 芯片与模块选型

SX1276/SX1278 是上一代广泛使用的 LoRa 收发器（1276 面向较宽频段、1278 面向 433MHz 等较低频段），生态成熟、资料多；SX1262 在功耗、接收灵敏度和抗阻塞能力上有改进，是新一代模块的常见选择。STM32WL 把 LoRa 收发器与 STM32 内核集成在单芯片内，适合希望减少器件数量、简化射频设计的方案。

模块层面，Ra-01、Ebyte E22、HopeRF 系列常常只是把收发器和必要的匹配网络封装成可焊模块，选型时要核对：频段、功率档位、是否带 TCXO（频偏对接收窗口对齐影响很大）、天线接口形式、模块自己的 SRRC/CE/FCC 认证覆盖范围与使用条件。

## 10. 网络部署选择

The Things Network（TTN）等公共网络适合原型验证和覆盖已经存在的城市；它的优势是免部署网关、社区覆盖广，代价是下行配额和速率策略受限、数据经过第三方。私有部署常见方案是 ChirpStack 一类开源网络服务器配自建网关，数据自主可控、参数可调，代价是网关选址、回传链路和运维都需要自己承担。

选择时要先算覆盖：单网关在城市环境覆盖数百米到数公里，具体取决于网关高度、天线增益、终端 SF 和建筑遮挡；用现场实测的 RSSI/SNR 反推所需网关数量，比标称距离可靠得多。

## 11. 常见问题与排查方向

**空中时间过长**：检查是否使用了过高的 SF，以及在当前链路质量下是否有必要；固定终端应开启 ADR。同时确认前导长度和载荷是否被无谓放大。

**占空比超限**：表现为法规测试不通过或网络服务器丢弃报文。核对目标区域的占空比条款与固件的发送节奏，把重传也计入占空比预算。

**网关覆盖与天线**：确认网关天线增益、馈线损耗和安装高度，避免把天线贴在金属机柜内侧；终端天线同样需要净空，见 [[05-Communication/07-无线通信-BLE-WiFi-Matter/001-无线通信基础与射频常识|无线通信基础与射频常识]]。

**上行丢失**：先区分是终端没发出去（占空比、发送失败）、网关没收到（覆盖、干扰、SF 不匹配），还是网络服务器丢弃（帧计数器、鉴权）。逐段用日志与抓包确认。

**OTAA 入网失败**：核对 DevEUI/AppEUI/AppKey 的字节序与烧录方式、区域参数是否与网关一致、Join 请求是否被网关正确转发，以及设备是否在多次失败后过度重试触发限流。功耗与电池寿命的核算方法见 [[07-Power-Management/05-低功耗设计/006-案例分析传感器节点寿命|传感器节点寿命案例分析]]。

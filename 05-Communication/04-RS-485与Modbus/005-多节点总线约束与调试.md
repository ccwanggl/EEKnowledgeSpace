# 多节点总线约束与调试

RS-485 系统的容量不是一个"最多支持 N 个节点"的数字，而是由总线电容、驱动器负载、空闲电平和轮询周期四项约束共同决定的结果。这些约束在 3 个节点的实验台上完全看不出来，到现场铺开 20 个节点后集中暴露。

## 1. 节点数约束的完整核算

| 约束 | 计算方式 | 典型边界 |
|---|---|---|
| 单位负载 | 每个节点按数据手册的 UL 值累加 | 传统 1 UL × 32 节点；1/8 UL 可放宽到 128~256 |
| 总线电容 | 电缆电容（按长度和单位电容）+ 各节点输入电容之和 | 高速率下总电容上限更低，需按速率核对 |
| 驱动器负载 | 终端电阻 + 偏置网络 + 各节点输入阻抗并联后的等效负载 | 等效负载不应低于驱动器额定最小负载 |
| 空闲电平 | 偏置网络在全部节点接入时的差分电压 | 必须大于接收阈值（200 mV）且留有余量 |
| 轮询周期 | 所有从站的请求、响应与静默间隔之和 | 必须小于系统要求的刷新周期 |

实践中的顺序是：先由速率和电缆长度确定总线电容是否可行，再核算驱动器负载与空闲电平，最后用轮询周期检查实时性。任何一项不满足，都要通过降低速率、减少节点、缩短距离或改用隔离/中继来解决。

**中继器**是扩展节点数和距离的常用手段：把总线分成若干段，每段独立满足物理层约束。代价是引入转发延迟，因此中继器的延迟要计入轮询周期，且高速率下可用段数会减少。

## 2. 轮询周期的计算与优化

轮询周期直接决定系统的刷新率，是实时性设计中最先要算清楚的数字。计算与实例见 [[05-Communication/04-RS-485与Modbus/004-Modbus软件实现|Modbus 软件实现]]，这里补充优化手段：

- **合并请求**：把同一从站的多个寄存器合并成一次读取（0x03 一次最多 125 个寄存器），帧数减少后静默间隔的开销显著下降。低速率下这一项的收益最大。
- **提高波特率**：直接缩短传输时间，但要求更短的静默间隔和更精确的帧分界，也对总线电容和距离提出更高要求。
- **减少从站数量**：把多个测点合并到同一个从站，或改用支持多从站聚合的网关。
- **分级轮询**：关键数据高频轮询，非关键数据低频轮询，而不是所有数据同一个周期。
- **避免近距离轮询**：一次只问一个寄存器、反复问同一个从站，是常见的实现浪费。

需要提醒的是：**轮询周期是平均值，不是保证值**。重试、异常响应、从站处理时间波动都会让某个轮次变长，设计时要为最坏情况留余量，而实时控制回路不能建立在"平均周期"上。

## 3. 分层排查方法

一次"通信不正常"的报告需要被拆成物理层、链路层、应用层三层分别确认，顺序不能颠倒：

**第一步，物理层**（不通或误码的所有情况都先做这一步）：

1. 断电测 A-B 之间的电阻，确认终端电阻数量与位置（应为约 60 Ω）。
2. 上电测空闲时的差分电压，确认偏置网络有效且偏在阈值之外。
3. 用示波器看一个字节的波形：边沿是否干净、是否有明显振铃、幅度是否足够。
4. 确认 A/B 定义在全系统一致（波形正常但收不到数据时优先怀疑接反）。
5. 测节点间地电位差，判断是否超出收发器共模范围。

**第二步，链路层**：

1. 用逻辑分析仪抓一次完整的请求与响应，核对帧边界是否正确、静默间隔是否满足 3.5 字符时间。
2. 核对波特率、数据位、校验位、停止位在所有节点上完全一致（一个从站配成 8E1 而其他是 8N1 时，通常表现为该从站永远不响应）。
3. 检查方向切换时序：发送波形末尾是否被截断、从站响应首字节是否丢失。

**第三步，应用层**：

1. 用 PC 上的 Modbus 调试软件模拟主站，逐个从站单独测试，确认单个从站本身正常。
2. 核对功能码与地址映射（含 0/1 起始的地址偏移）。
3. 核对多寄存器数据的字序约定。
4. 检查从站对越界地址、超限数量的异常响应是否符合规范。

分层排查的价值在于：如果物理层没过，就完全不需要去分析报文；而在物理层没问题的前提下反复改协议代码，通常是在浪费时间。

## 4. 现场故障对照表

| 现象 | 高概率原因 | 定位手段 |
|---|---|---|
| 所有从站都不响应 | 主站方向切换异常、终端缺失、总线短路 | 示波器看主站发送波形与总线波形 |
| 单个从站不响应 | 该从站地址/波特率/校验配置错误、接线脱落 | 单独接入该从站测试 |
| 偶发 CRC 错误 | 干扰、屏蔽或接地不当、波特率偏差、总线过长 | 错误计数统计 + 波形观察 |
| 偶发超时（无响应） | 从站忙、轮询间隔太短、方向切换过早 | 看响应是否被截断、延长超时验证 |
| 首字节丢失 | 方向切换过晚或从站响应太快 | 逻辑分析仪看响应起始位置 |
| 末字节被截断 | 方向切换过早（未等 TC 标志） | 核对发送完成等待逻辑 |
| 距离增加后失败 | 缺终端、总线电容超限、地电位差 | 测电阻、测差分电平 |
| 变频器启停时出错 | 共模干扰、无隔离 | 加共模电感、改隔离方案验证 |
| 增加节点后失败 | 驱动器负载过重、空闲电平不足、电容超限 | 重新核算偏置与负载 |
| 读多个寄存器时数据错乱 | 接收缓冲不足、帧分界错误、字序不符 | 核对缓冲长度与解析逻辑 |
| 长时间运行后偶发失败 | 电气参数随温度漂移、接插件氧化 | 温度循环测试、检查接插件 |

## 5. 可靠性设计要点

RS-485 + Modbus 本身没有链路层纠错，应用层需要补上这些机制：

- **超时与重试上限**：读操作可重试，写操作要考虑幂等性。
- **通信状态与安全值**：连续多次失败后，从站数据应被标记为无效，使用方（控制逻辑）要使用安全默认值而不是上次的旧值。这一点在采集类系统中常被忽略，导致控制端基于过期数据做决策。
- **错误统计与上报**：按从站记录超时、CRC 错误、异常响应次数。现场问题几乎都能通过错误分布的差异定位到具体节点或具体时段。
- **看门狗与恢复**：从站长时间无请求或总线异常时，应能通过重新初始化 UART 与外设恢复，而不是等人工断电。
- **上电时序**：所有节点上电期间不得驱动总线；主站应在系统上电稳定后才开始轮询，并在启动阶段允许从站有额外的初始化时间。

## 6. 交付与验收清单

1. 接口定义文档：A/B 定义、波特率与帧格式、终端与偏置位置、隔离方案。
2. 从站地址表与寄存器点表（含地址偏移约定与数据类型/字序）。
3. 轮询周期计算书（含最坏情况）与总线负载率。
4. 节点数核算结果（UL、电容、驱动器负载、空闲电平）。
5. 错误统计与通信状态上报的实现说明。
6. EMC 测试结论与必要的保护元件清单。
7. 现场排查手册：分层检查步骤与常用工具。

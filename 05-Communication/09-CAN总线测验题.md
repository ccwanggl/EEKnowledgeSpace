# CAN 总线测验

分别从仲裁、物理层和调试证据作答。复测时让 AI 保持机制不变，只替换 ID、终端条件或故障现象。

## 1. 比较两个消息 ID

两个节点同时开始发送经典 CAN 的标准格式数据帧，ID 分别为 0x120 和 0x123。谁继续发送？另一个节点在什么时候知道自己失去仲裁？

<details><summary>核对</summary>

0x120 先继续发送。标准 ID 从高位依次发送，在第一个不同位，0x120 发显性 0，0x123 发隐性 1 却读到显性 0，因此后者退出仲裁。[[05-Communication/03-CAN总线/001-总线模型与仲裁机制|总线模型与仲裁机制]]

</details>

## 2. 解释两个终端电阻

总线断电，假定收发器等其他并联路径的影响可忽略，两端各有一个 120 Ω 终端。测 CAN_H 与 CAN_L 之间的电阻应约为多少？哪种情况可能读到约 120 Ω？

<details><summary>核对</summary>

两个 120 Ω 终端并联约为 60 Ω。少装一个终端或其中一路断开时可能约为 120 Ω，仍要核对实际拓扑和测量路径。[[05-Communication/03-CAN总线/004-物理层与拓扑设计|物理层与拓扑设计]]

</details>

## 3. 区分链路问题与应用问题

发送节点不断尝试发送，控制器报告 ACK 错误。画出你要观察的信号和日志，再说明应优先验证哪两项条件。

<details><summary>核对</summary>

先确认是否有另一个节点在线、处于可参与通信的模式，再确认双方位时序与连接是否允许接收端正确接收帧。用错误状态、波形和节点配置交叉核对。收到 ACK 只能说明至少一个接收节点确认了链路层帧。[[05-Communication/03-CAN总线/007-嵌入式实现与调试|嵌入式实现与调试]]

</details>

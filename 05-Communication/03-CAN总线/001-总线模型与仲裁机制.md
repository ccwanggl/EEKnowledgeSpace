# 总线模型与仲裁机制

CAN 把"谁可以发"这个问题的答案放在帧本身里：帧的标识符越小，优先级越高。节点在发送的同时监听总线，一旦发现自己发的位与总线实际电平不符就立即退出，让位优先级更高的帧继续。整个过程不损失数据，也不需要重传被抢占的帧——这就是非破坏性仲裁，也是 CAN 与其他总线最本质的区别。

## 1. 多主广播模型

CAN 总线没有主从之分，任何节点在总线空闲时都可以开始发送。所有节点都能收到每一帧，由接收方根据标识符决定是否处理。这个模型带来两个直接后果：

- 节点之间没有"请求-应答"的强制关系，一个节点发送的帧可能没有任何接收方，发送方无法从总线层面知道这一点（ACK 只表示"至少有一个节点正确接收"）。
- 增加或删除节点不需要修改其他节点的配置，前提是 ID 分配有统一规划且总线负载还有余量。

总线空闲的定义是：连续检测到 11 个隐性位（3 位帧间隔 + 8 位总线空闲）。这个规则与错误处理机制耦合，是理解错误界定和恢复流程的基础。

## 2. 标识符即优先级

CAN 用标识符（ID）标识消息内容而不是节点地址。这带来一个工程上的好处和一个约束：

- 内容寻址意味着同一个 ID 可以由不同节点在不同时刻发出（比如多个传感器上报同一类数据），也可以被多个节点同时接收（广播），组播和广播不需要额外的地址机制。
- 优先级由 ID 数值决定，数值越小优先级越高。ID 分配因此不是随意的编号，而是一次优先级设计。安全相关的帧（碰撞信号、故障停机）必须用最小的一批 ID。

标准帧用 11 位 ID，扩展帧用 29 位。两者可以在同一条总线上共存，仲裁规则保证标准帧优先：标准帧的 IDE 位为显性，扩展帧在该位置为隐性，因此当标准帧和扩展帧的 ID 前 11 位相同时，标准帧赢得仲裁。

## 3. 逐位仲裁怎么工作

CAN 的位电平遵循"线与"逻辑：显性（逻辑 0）会覆盖隐性（逻辑 1），只要有任意一个节点在发送显性位，总线上就是显性。

仲裁发生在仲裁场（ID + RTR）和后续的若干控制位。过程如下：

1. 多个节点在总线空闲时同时开始发送，都先发 SOF 显性位。
2. 每个节点逐位发送自己的 ID，同时读回总线电平。
3. 若某节点发送隐性位但读回显性位，说明有另一个节点在发送同一个位置上的显性位，即对方的 ID 数值更小、优先级更高。该节点立即停止发送，转为接收状态。
4. 赢得仲裁的节点继续发送，它甚至不知道自己经历过仲裁——发送过程中没有丢失任何位。

由于所有竞争节点在退出点之前发送的位完全相同，仲裁过程本身就是一次有效的位传输。失败的节点会在总线空闲后自动重试（如果是控制器自动重发），这一帧的延迟只增加了一次仲裁的时间。

仲裁场的最后一个位是 RTR（远程发送请求），它在数据帧中为显性、在远程帧中为隐性，因此同 ID 的数据帧优先于远程帧。

## 4. 为什么长 ID 前缀相同的帧不会浪费带宽

一个常见的误解是"仲裁失败的节点浪费时间发送了一部分帧"。实际上，仲裁逐位进行，失败节点退出的位置越早，浪费的位越少。ID 前几位就不同的帧之间，冲突只持续几位；ID 完全相同的两帧才会一直仲裁到数据场（在数据场发生位不一致会触发错误而不是仲裁，因为此时已进入非仲裁阶段）。

这解释了两条 ID 分配经验：让同类消息的 ID 共享高位前缀，可以让仲裁尽早分出胜负；避免两个高优先级消息使用完全相同的 ID。

## 5. 错误检测的五种机制

CAN 链路层的可靠性来自五种互补的检测手段，它们覆盖的故障类型不同：

| 机制 | 检测什么 | 由谁执行 |
|---|---|---|
| 位监控 | 发送方读回的位与自己发送的位是否一致（仲裁场除外） | 发送节点 |
| 位填充 | 连续 5 个同极性位后是否出现第 6 个 | 所有节点 |
| CRC | 15 位 CRC 校验帧内容 | 接收节点 |
| 帧格式检查 | 固定格式位（CRC 定界符、ACK 定界符、EOF 等）是否出现非法电平 | 所有节点 |
| ACK 检查 | 发送方在 ACK 槽是否读到显性位 | 发送节点 |

位填充的规则是：发送方在连续 5 个同极性位之后插入一个反极性位，接收方自动删除。它的作用是保证足够的电平跳变让接收方维持同步，同时让第 6 个同极性位成为可检测的错误标志。位填充也意味着帧的实际位数取决于数据内容，最坏情况下每 5 位插入 1 位，计算总线负载率时必须考虑这一点。

## 6. 错误计数与节点状态机

每个节点维护两个计数器：发送错误计数 TEC 和接收错误计数 REC。检测到错误时相应计数器加 8（发送方）或加 1（接收方），成功发送或接收时减 1。计数器的大小决定节点处于三种状态中的哪一种：

| 状态 | 进入条件 | 行为 |
|---|---|---|
| 主动错误（Error Active） | TEC 与 REC 均 ≤ 127 | 检测到错误时发送主动错误标志（6 个显性位） |
| 被动错误（Error Passive） | TEC 或 REC > 127 | 检测到错误时发送被动错误标志（6 个隐性位），不再干扰总线 |
| 总线关闭（Bus Off） | TEC > 255 | 从总线上脱离，不再参与通信 |

这套机制让"持续出错的节点"自动降级，避免一个故障节点反复用错误帧打断正常通信。被动错误节点仍可正常收发，只是错误标志不再具有破坏性。

**总线关闭的恢复**是现场最常见的问题之一。控制器通常支持两种恢复方式：硬件自动恢复（检测到 128 次连续 11 个隐性位后清除计数器）和软件干预（重新初始化控制器）。工程上一般倾向软件控制恢复，因为需要记录进入总线关闭的原因（通常是接线错误、终端电阻缺失或波特率不匹配），否则会看到"设备反复掉线"的现象而找不到根因。

## 7. 错误界定与故障受限

检测到错误后，节点发送错误标志，随后的 8 个位是错误定界符，总线在这一段保持隐性以让其他节点识别出错误帧。由于错误标志会破坏当前帧，发送方必然重发该帧。如果错误反复发生，计数器持续累加，节点逐步降级，这一过程称为故障受限（fault confinement）。

CAN FD 在错误处理上引入了额外的机制：当数据段启用更高波特率时，CRC 场的可靠性下降，因此 FD 增加了 CRC 定界符后额外位的计数规则和更严格的填充策略，具体字段见 [[05-Communication/03-CAN总线/003-CAN-FD扩展|CAN FD 扩展]]。

## 8. 仲裁机制的工程影响

- **延迟有上界**：高优先级帧的最坏延迟可以被计算出来，这是 CAN 能用于动力和底盘控制的前提。
- **低优先级帧可能饥饿**：在总线负载率很高的场景中，低优先级帧会反复仲裁失败。设计时要为每类消息检查最坏延迟，而不只是平均延迟。
- **ID 分配是设计文档**：ID 表需要版本管理，新增节点时要在表里找空位而不是随便取一个数。诊断与标定用的 ID 段通常留给 UDS/J1939 等高层协议。

# 嵌入式 C 编程测验题

这组题检查语言规则、寄存器访问、并发、DMA、诊断和实时控制，不要求背诵某颗 MCU 的寄存器地址。建议学完 [[01-Foundations/08-嵌入式C编程/000-嵌入式C编程|嵌入式 C 编程]] 后作答，并说明判断依据。

## 一、概念与判断，共 40 分

每题 5 分。选择最准确的一项。

### 1. 乘法在哪种类型中执行

```c
uint16_t a = 50000U;
uint16_t b = 2U;
uint32_t result = a * b;
```

关于这段代码，哪项判断正确？

A. 接收变量是 `uint32_t`，乘法必定在 32 位无符号类型中进行

B. 乘法前会发生整数提升，实际运算类型取决于实现中 `int` 的范围

C. `uint16_t` 乘法由 C 标准规定为饱和运算

D. 只要 MCU 是 32 位，表达式就与编译器无关

<details>
<summary>答案与解析</summary>

答案：B。

赋值目标不决定乘法的运算类型。两个操作数先经历整数提升；在某些实现中能提升为 `int`，在 `int` 无法表示全部 `uint16_t` 值的实现中可能提升为 `unsigned int`。要明确表达 32 位无符号乘法，可在运算前把操作数转换成 `uint32_t`。见 [[01-Foundations/08-嵌入式C编程/002-整数、位运算与定点数值|整数、位运算与定点数值]]。
</details>

### 2. `volatile` 能提供什么

哪项属于 `volatile` 的合理用途？

A. 让 `counter++` 在中断和主循环之间原子执行

B. 充当发布 DMA 缓冲区的内存屏障

C. 表达内存映射寄存器访问具有外部可观察性

D. 防止任何形式的编译优化

<details>
<summary>答案与解析</summary>

答案：C。

`volatile` 约束对易失对象访问的优化，但不提供复合操作原子性、互斥、缓存一致性或通用内存顺序。见 [[01-Foundations/08-嵌入式C编程/004-寄存器访问、volatile与硬件抽象|寄存器访问、volatile 与硬件抽象]]。
</details>

### 3. 清除 W1C 标志

参考手册明确说明 `STATUS` 的 `UPDATE` 位为 W1C，写 1 清除。没有其他特殊约束时，哪种写法更符合语义？

A. `timer->STATUS &= ~UPDATE_Msk;`

B. `timer->STATUS |= UPDATE_Msk;`

C. `timer->STATUS = UPDATE_Msk;`

D. `timer->STATUS = 0U;`

<details>
<summary>答案与解析</summary>

答案：C。

直接写入要清除的位，避免读改写把读取到的其他 W1C 标志一并写回。该结论只适用于手册明确为 W1C 的寄存器，W0C、读清除和普通读写寄存器需要不同操作。
</details>

### 4. 指针转换意味着什么

把 `uint8_t *` 转换成 `uint32_t *` 后，哪项仍需要单独证明？

A. 只有地址非零

B. 只有存储空间位于 RAM

C. 对象生命周期、边界、对齐和访问类型都成立

D. 强制转换已经使访问合法

<details>
<summary>答案与解析</summary>

答案：C。

强制转换不会创建对象、延长生命周期或修复未对齐地址。见 [[01-Foundations/08-嵌入式C编程/003-指针、对象生命周期与内存安全|指针、对象生命周期与内存安全]]。
</details>

### 5. 超级循环中的延时

主循环依次处理传感器、通信和保护。某一步调用阻塞式 `delay_ms(100)`，最直接的系统影响是什么？

A. 只影响调用延时的模块

B. 推迟同一主循环中其他协作步骤，可能造成期限违约

C. 自动把该模块转换为低优先级任务

D. 中断存在时所有影响都被消除

<details>
<summary>答案与解析</summary>

答案：B。

超级循环是协作式调度，一个步骤不返回会推迟其他步骤。中断仍可能运行，但不能代替被阻塞的后台处理。见 [[01-Foundations/08-嵌入式C编程/006-超级循环、状态机与事件驱动|超级循环、状态机与事件驱动]]。
</details>

### 6. DMA 完成后的缓冲区

带数据缓存的 MCU 使用 DMA 接收数据。DMA 完成中断到达后，CPU 读取缓冲区前应怎样做？

A. 把缓冲区声明成 `volatile` 即可

B. 总是清理缓存，不需要看传输方向

C. 按平台规定执行接收方向所需的缓存失效、屏障和所有权交接

D. 再启动一次 DMA，第一次数据才会可见

<details>
<summary>答案与解析</summary>

答案：C。

具体缓存维护取决于平台、缓存策略、方向、地址和长度。`volatile` 不能让缓存与主存自动一致。见 [[01-Foundations/08-嵌入式C编程/007-DMA、缓冲区与外设数据通路|DMA、缓冲区与外设数据通路]]。
</details>

### 7. 断言适合检查什么

哪项更适合用内部断言检查？

A. 串口收到校验失败的外部数据

B. 用户请求了暂不支持的速度

C. 内部状态枚举出现设计上不可能的取值

D. 外设在规定时间内没有响应

<details>
<summary>答案与解析</summary>

答案：C。

外部错误和设备超时应进入正常错误路径。断言用于检查程序不变量和内部缺陷。见 [[01-Foundations/08-嵌入式C编程/008-错误处理、断言与故障诊断|错误处理、断言与故障诊断]]。
</details>

### 8. 怎样判断控制周期满足实时要求

哪项证据最有说服力？

A. 控制函数平均执行时间低于周期

B. 调试版连续运行一分钟没有复位

C. 发布配置下测得端到端最坏时间，并计入采样、干扰和 PWM 生效窗口

D. 控制函数没有使用浮点数

<details>
<summary>答案与解析</summary>

答案：C。

实时要求关心截止时间。平均时间会隐藏偶发超期，也没有覆盖采样、调度和输出实际生效的延迟。见 [[01-Foundations/08-嵌入式C编程/010-实时控制固件的架构、时序与验证|实时控制固件的架构、时序与验证]]。
</details>

## 二、代码审阅，共 40 分

每题 10 分。指出问题、触发条件和可行修订，只有结论没有理由最多得一半分。

### 9. 清标志与共享计数器

```c
volatile uint32_t pulse_count;

void TIMER_IRQHandler(void)
{
    TIMER->STATUS &= ~TIMER_UPDATE_Msk;
    pulse_count++;
}
```

主循环也会执行 `pulse_count++`。请指出至少三个需要核实或修订的问题。

<details>
<summary>参考答案</summary>

1. 必须查参考手册确认 `STATUS` 的清除语义。若标志是 W1C，读改写可能错误清除其他标志，应直接写入规定掩码。
2. 应先确认中断来源，避免同一向量中的其他标志造成误处理或中断风暴。
3. `volatile` 不能让 `pulse_count++` 原子化。ISR 和主循环都写会丢失更新，应改成单写者、短临界区或经平台验证的原子操作。
4. 计数回绕是否允许、回绕后怎样解释也应写入契约。
5. ISR 名称和定义方式应符合启动文件、编译器和器件头文件约定，不能假设所有平台都相同。
</details>

### 10. 环形缓冲区接口

```c
uint8_t rb_get(void)
{
    if (head == tail) {
        return 0U;
    }
    uint8_t value = buffer[tail];
    tail = (tail + 1U) % BUFFER_SIZE;
    return value;
}
```

生产者在 UART ISR，消费者在主循环。请审阅接口和并发契约。

<details>
<summary>参考答案</summary>

- 返回 `0` 无法区分队列为空和有效字节 `0`，可改为 `bool rb_try_pop(uint8_t *value)`。
- 需要明确单生产者单消费者约束、满队列策略和索引类型。
- `head`、`tail` 的访问是否原子以及数据写入与索引发布的顺序，需要平台原子操作、临界区或经过证明的 SPSC 实现。只加 `volatile` 不够。
- `% BUFFER_SIZE` 并非错误，但若改成按位与，必须保证容量为二次幂并通过静态断言固定约束。
- 还要统计溢出和丢弃，便于验证最坏数据率。
</details>

### 11. 直接发送结构体

```c
typedef struct __attribute__((packed)) {
    uint8_t type;
    uint32_t timestamp;
    int16_t current;
} frame_t;

uart_send((const uint8_t *)&frame, sizeof frame);
```

为什么这段代码不适合作为跨平台协议格式？

<details>
<summary>参考答案</summary>

- `packed` 是编译器扩展，布局保证依赖工具链。
- 多字节字段的端序没有定义。
- 未对齐成员访问可能降低性能，某些平台会触发故障。
- 协议缺少显式版本、长度和完整性校验。
- 结构体变化会直接改变线上格式。

更稳妥的做法是逐字段编码到字节数组，显式规定端序、范围、长度和校验，并用字节级测试向量验证。
</details>

### 12. 控制 ISR 中的诊断

```c
void ADC_IRQHandler(void)
{
    current_sample_t sample = adc_read_sample();
    foc_step(&sample);
    printf("ia=%ld ib=%ld\n", sample.ia, sample.ib);
}
```

请给出适合实时控制的修订方向。

<details>
<summary>参考答案</summary>

- 先按手册确认中断来源和清除顺序，并验证 `adc_read_sample` 取得的是完整、同一时刻对应的样本。
- `foc_step` 必须固定长度、无阻塞，并测量包含抢占干扰的最坏执行时间。
- 格式化和阻塞式输出不应位于控制 ISR。可写入固定大小追踪事件或低成本快照，由后台异步输出。
- `int32_t` 不保证与 `long` 类型相同，格式化输出应使用 `<inttypes.h>` 的对应宏或经过检查的显式转换。
- 样本应带序号、时间戳、单位和有效性，控制器要处理无效或过期数据。
- 输出占空比应在规定的 PWM 更新窗口前提交，并验证实际生效时刻。
</details>

## 三、工程设计，共 20 分

### 13. 设计一个 DMA 双缓冲采样协议，10 分

ADC 连续采样两组电流通道，DMA 使用 A、B 两块缓冲区，控制任务处理完整数据块。写出最少需要定义的状态和异常路径。

<details>
<summary>参考答案</summary>

合格设计应包含：

- A、B 缓冲区至少区分“可供 DMA 写入”“DMA 正在写”“已完成待处理”“CPU 正在处理”状态；
- DMA 完成事件携带缓冲区身份和序号，不能只设置一个可能被覆盖的布尔标志；
- CPU 处理完成后显式归还缓冲区；
- 定义 CPU 超时导致 DMA 即将覆盖未处理数据时的策略，并累计丢批计数；
- 带缓存平台在交接点执行目标平台规定的缓存维护、对齐和屏障；
- DMA 错误、取消、外设复位和控制停机都说明缓冲区归属；
- 用最高采样率和最大后台干扰验证最坏处理时间小于缓冲区复用间隔。
</details>

### 14. 制定 FOC 周期验收方案，10 分

控制周期为固定频率。说明怎样证明采样到 PWM 更新满足期限，并列出至少四类测试条件。

<details>
<summary>参考答案</summary>

验收应从 ADC 物理采样时刻开始，到新占空比在 PWM 更新点实际生效结束。分别测量转换、DMA 或 ISR 分发、控制计算、寄存器提交和更新等待，并加入更高优先级中断、总线与缓存等干扰。记录最大值、抖动和错过更新窗口的次数，发布配置必须满足预算并保留设计余量。

测试条件可包括：最高通信与 DMA 负载、最差允许时钟配置、发布优化、无调试器启动、故障与保护同时发生、参数切换、温度和电压边界、长时间运行、缓存命中与未命中的不同路径。算法结果还应与离线参考模型或记录数据回放比较。
</details>

# 检索练习、间隔复习与交错学习

重读时产生的熟悉感，不能保证离开材料后仍能提取和应用。检索练习要求先从记忆中重建答案，再用资料反馈纠正；间隔复习把这种提取安排在不同时间；交错练习让学习者在多个候选方法之间作选择。

## 1. 一次有效检索包含反馈

```mermaid
flowchart LR
    A["不给答案，尝试回忆或解决"] --> B["写出过程和置信度"]
    B --> C["对照可靠资料"]
    C --> D["标记遗漏、错误和猜测"]
    D --> E["用自己的过程重做"]
    E --> F["延迟后再次检索"]
```

只看题目后立刻翻答案，提取强度很低。答错后不反馈，又可能巩固错误。反馈需要指出正确结果，也要说明错误发生在概念、条件、方法选择还是计算步骤。

## 2. 工程知识需要多种检索题

| 目标 | 题目形式 | 示例 |
|---|---|---|
| 回忆事实与条件 | 简答、填图、单位 | MOSFET 安全工作区受哪些条件限制 |
| 重建模型 | 空白纸推导、框图 | 从电机电压方程写出 $dq$ 轴模型 |
| 区分相似概念 | 对比和反例 | 带宽不足与采样混叠怎样在波形上区分 |
| 选择方法 | 混合题型 | 这个节点该用万用表、示波器还是差分探头 |
| 诊断故障 | 现象到假设 | 电流环出现二倍电频率波动有哪些候选原因 |
| 设计与权衡 | 开放约束题 | 在成本和带宽限制下选择电流采样方案 |

只做定义卡片会提高术语回忆，却很难覆盖推导、方法选择和故障诊断。闪卡适合短而明确的知识单元，复杂技能应保留完整问题、代码、仿真或实验。

## 3. 先回答，再查看资料

检索可以很短：

- 合上书写出本节三个关键关系和适用条件；
- 看原理图前预测关键节点电压与极性；
- 运行仿真前画出预期波形；
- 编译前列出可能的边界错误；
- 测量前写出数量级、带宽和异常特征。

预测会留下可对照的基线。结果不符时，能判断是记忆错误、模型错误还是实现错误，复盘也不再依赖事后解释。

## 4. 复习间隔跟着保持目标调整

分散学习通常比连续重复更有利于延迟保持，但不存在适用于所有材料的固定间隔。合适的间隔受以下因素影响：

- 希望保持多久；
- 材料难度和已有基础；
- 每次检索能否成功；
- 反馈质量；
- 知识是否在项目中自然重复使用；
- 后续任务是否要求迁移而非原样回忆。

可以从较短间隔开始，在能够费力但基本成功地提取后逐渐拉长。连续失败说明材料过大、线索不足或前置知识缺失；每次毫不费力则可以增加间隔或改成更深的题型。

## 5. 交错练习训练方法选择

连续做十道同类型题时，题目顺序已经透露了方法。交错排列 RC、RL、RLC、运放和采样题，学习者需要根据题目特征选择模型。Taylor 与 Rohrer 的数学学习实验表明，交错练习可能降低练习阶段的流畅度，却改善后续方法选择和测试表现。

交错不适合在尚未看懂基本步骤时立即使用。较稳妥的顺序是：

1. 用少量完整例题建立基本结构；
2. 完成同结构的短组练习；
3. 把容易混淆的方法放入同一组；
4. 延迟后加入参数和场景变化；
5. 让题目中不再标注所属章节。

交错效果在任务间并不一致。需要识别策略的题目通常更合适，固定动作的早期练习可能先从成组练习受益。

## 6. 置信度帮助发现误判

每次回答后记录低、中、高置信度，再与结果比较：

| 结果 | 置信度 | 处理方式 |
|---|---|---|
| 正确 | 高 | 延长间隔或提高题目深度 |
| 正确 | 低 | 查明依据，反馈能巩固尚不稳定的知识 |
| 错误 | 低 | 补前置知识或增加线索后重做 |
| 错误 | 高 | 优先复盘，通常存在稳定误解或错误规则 |

只统计正确率会漏掉高置信错误。工程设计中的高置信错误更可能进入代码、原理图和测试结论，应形成明确的纠错记录。

## 7. 闪卡怎样写才有用

合适的卡片：

- 问题只有一个清楚的提取目标；
- 答案包含必要条件和单位；
- 能在短时间内判断对错；
- 来源和版本可追溯；
- 对易混概念要求解释区别；
- 公式卡要求说明变量、假设和适用范围。

不适合直接制成卡片的内容包括长篇推导、整段代码、复杂排障流程和可以随时查阅的型号表。它们可以转成“下一步做什么”“哪条边界最容易漏”或“如何判断方法不适用”这类提取问题。

## 8. 从笔记生成练习，再回写错误

知识笔记记录较稳定的解释，练习记录具体回答和错误。推荐关系为：

```mermaid
flowchart LR
    A["概念或推导笔记"] --> B["生成检索题和变式题"]
    B --> C["独立回答"]
    C --> D["错误与置信度记录"]
    D --> E["修正笔记、题目或前置链接"]
    E --> F["延迟复测"]
```

当一道题反复失败时，不要只提高出现频率。检查答案是否含糊、题目是否过大、知识笔记是否缺条件，以及错误是否来自另一项前置能力。

## 9. 简单的复习记录

```markdown
主题：
检索任务：
日期：
是否独立完成：
置信度：低 / 中 / 高
错误类型：概念 / 条件 / 方法 / 计算 / 实现
反馈来源：
下一次复测条件：
```

复测条件可以写“完成当前项目后”“参数改变时”或“间隔一周”，不必把所有知识强行塞进同一种日历算法。

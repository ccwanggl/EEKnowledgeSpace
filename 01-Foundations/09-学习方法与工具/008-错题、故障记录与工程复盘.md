# 错题、故障记录与工程复盘

答案错误、仿真不收敛、板卡损坏和偶发通信故障都能提供反馈，前提是记录保留了预期、证据和条件。只写“粗心”“接线错误”或“代码有 bug”，下一次很难判断相同原因是否再次出现。

## 1. 从预期和实际差异开始

```markdown
任务与版本：
预期结果及依据：
实际结果：
发生条件：
最小复现步骤：
原始证据：
影响范围：
当前状态：调查中 / 已定位 / 已修复 / 已验证
```

预期需要在看到结果前形成。没有事前预测时，复盘容易根据现象重写解释，遗漏当时真正采用的假设。

## 2. 错误分类帮助选择修正方式

| 类型 | 典型表现 | 合适的修正 |
|---|---|---|
| 概念 | 因果或对象理解错误 | 回到模型、反例和辨析题 |
| 条件 | 忘记适用范围、单位或参考方向 | 在推导和检查表中显式写条件 |
| 方法 | 面对问题选择了错误工具或模型 | 交错相似问题，训练方法选择 |
| 计算 | 代数、数量级、舍入和单位错误 | 针对薄弱步骤做短练习和自动检查 |
| 工具 | 量程、求解器、编译选项或配置错误 | 保存配置、建立自检和已知基线 |
| 实现 | 代码、原理图、PCB 或装配偏离设计 | 评审差异、测试接口和版本控制 |
| 测量 | 探头负载、接地、带宽或参考点错误 | 重建测量模型并交叉验证 |
| 流程 | 缺少评审、验收、回归或安全步骤 | 修改模板、门禁和自动测试 |
| 沟通 | 规格、接口或责任边界含糊 | 把约定写成可测试接口和版本 |

“粗心”只描述感受，不说明控制措施。把小数点看错可能来自单位表示混乱、缺少数量级检查或界面截断，不同原因需要不同修正。

## 3. 故障记录保留时间线

复杂故障会经历多个假设和操作。按时间记录：

| 时间 | 操作或变化 | 观察 | 推论 | 下一步 |
|---|---|---|---|---|
| T0 | 故障出现 | 原始波形和日志 | 尚未判断 | 保存现场 |
| T1 | 更换探头 | 尖峰消失 | 测量连接可能参与 | 缩短地线复测 |
| T2 | 恢复原探头并改地弹簧 | 尖峰仍消失 | 长地线是主要原因 | 建立标准接法 |

删除失败假设会让记录看起来更整洁，却失去排除过程。保留失败假设及其证据，可以防止后来者重复同一实验。

## 4. 根因需要因果链和验证

根因分析可以从“什么条件使故障成为必然或更可能”展开：

1. 找到最接近现象的直接机制；
2. 追溯什么设计、实现或流程允许它发生；
3. 为每个因果节点寻找证据；
4. 设计能区分候选原因的测试；
5. 修复后在原复现条件下验证；
6. 加入回归测试或防错检查。

反复问“为什么”可以帮助追溯，但次数没有固定意义。没有证据的更深一层解释仍然只是猜测。

## 5. 区分修复、缓解和绕过

- **修复**改变导致问题的机制；
- **缓解**降低发生概率或影响；
- **检测**让问题更早暴露；
- **绕过**避开触发条件；
- **接受**在明确风险和边界后不再改变。

比如降低 PWM 频率后过流消失，可能只是绕过采样窗口不足。要判断根因，还需测量 ADC 触发、放大器建立和有效采样区间。

## 6. 修复后必须重放原故障

验证至少包含：

- 原复现条件下故障不再出现；
- 修复机制的中间量符合预期；
- 正常场景没有明显退化；
- 参数、温度、负载和时序边界得到抽样；
- 重启、重新编译或重新装配后仍可复现结果；
- 回归测试能够在恢复旧错误时再次失败。

只看系统恢复工作，无法排除故障暂时消失、测量方法改变或测试条件没有对齐。

## 7. 把一次错误转成长期资产

| 错误产出 | 适合写到哪里 |
|---|---|
| 稳定的新概念或边界 | 主题笔记 |
| 易忘条件 | 检索题或闪卡 |
| 重复操作遗漏 | 检查表和项目模板 |
| 可自动判断的行为 | 单元测试、集成测试或脚本 |
| 仪器和接线要求 | 测量流程或夹具说明 |
| 设计取舍 | 决策记录 |
| 特定版本故障 | 项目故障日志和问题跟踪 |

不是每次错误都需要写成长文。判断标准是它是否会影响后续方法、设计或检查动作。

## 8. FOC 故障复盘示例

### 现象

电机低速运行平稳，速度提高后 $i_q$ 出现周期尖峰并触发过流。

### 候选原因

- ADC 采样落入开关噪声区；
- 电流放大器在共模跃迁后尚未建立；
- 电流重构在窄脉冲区失效；
- 编码器角度跳变；
- 真实过流或电流探头饱和；
- PWM 更新与采样触发错位。

### 区分测试

同时采集 PWM、ADC 触发、原始 ADC 码、估算角度和故障信号，逐步改变调制比与采样位置。若尖峰跟随采样位置而不跟随机械角度，可以优先检查采样与建立；若原始码稳定而变换后异常，再检查角度与软件路径。

### 可复用产出

把有效采样窗口公式写入主题笔记，把 PWM 与 ADC 触发测量加入上电检查，把高调制比场景加入回归测试。

## 9. 复盘只讨论能改变的动作

一次复盘可以回答：

- 哪项预期与证据不一致；
- 哪个假设最晚才被验证；
- 哪项记录缺失拖慢了定位；
- 哪个测试最有效地区分了原因；
- 哪项修改需要形成检查表或自动测试；
- 还有哪些边界没有验证。

“加强学习”“以后仔细”没有定义动作。改成“所有电压结果在提交前进行单位和数量级检查”“示波器截图同时保存探头倍率与带宽设置”，才能在下一次观察是否执行。

## 10. 关闭问题的条件

- [ ] 现象和复现条件足够明确；
- [ ] 根因有证据，不只与修复同时发生；
- [ ] 修复、缓解和绕过已经区分；
- [ ] 原故障被重放，修复后通过；
- [ ] 正常功能和关键边界经过回归；
- [ ] 代码、硬件、配置和测试版本可以对应；
- [ ] 稳定结论进入主题笔记或检查表；
- [ ] 未解决风险和再次打开条件已经写明。

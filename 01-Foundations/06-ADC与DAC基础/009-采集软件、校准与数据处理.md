# 采集软件、校准与数据处理

采集软件负责配置时序、接收原始码、识别异常、完成校准并转换为工程量。代码必须保留原始码和状态信息，避免过早换算或滤波掩盖硬件问题。

## 1. 初始化顺序

常见初始化流程为：

1. 配置参考、电源和模拟前端，等待规定启动时间；
2. 配置 ADC 时钟、分辨率、采集时间、触发和通道；
3. 执行器件支持的内部校准；
4. 清除旧状态并丢弃数据手册要求的初始样值；
5. 配置 DMA、缓存和溢出检测；
6. 启动定时器或外部触发；
7. 验证实际采样率、通道顺序和时间戳。

不同 MCU 和外部 ADC 的顺序不同，应以对应参考手册和数据手册为准。

## 2. 轮询读取需要处理失败路径

最小的 HAL 风格示例应检查每一步返回值：

```c
bool adc_read_once(uint32_t *code)
{
    if (code == NULL) {
        return false;
    }

    if (HAL_ADC_Start(&hadc1) != HAL_OK) {
        return false;
    }

    if (HAL_ADC_PollForConversion(&hadc1, ADC_TIMEOUT_MS) != HAL_OK) {
        (void)HAL_ADC_Stop(&hadc1);
        return false;
    }

    *code = HAL_ADC_GetValue(&hadc1);
    return HAL_ADC_Stop(&hadc1) == HAL_OK;
}
```

这段代码只表达错误处理结构。实际项目还要确认 HAL 版本、校准调用、过采样配置、触发模式和超时单位。周期采集通常更适合定时器触发加 DMA，而不是在主循环反复启动和停止 ADC。

## 3. DMA 缓冲区设计

连续采样常用双缓冲或环形缓冲。处理端必须在下一次覆盖前消费数据，并记录：

- DMA 半满、全满事件；
- 缓冲区序号和采样时间范围；
- 通道交织顺序；
- 溢出、丢帧和错误计数；
- CPU 缓存一致性；
- 处理最坏耗时。

中断中只做必要的状态切换和通知，把滤波、标定和通信放到可调度上下文。

## 4. 原始码到工程量

不建议把所有 ADC 都写成

```c
voltage = 3.3f * code / 4096.0f;
```

这个表达式隐含了理想 $3.3\ \text V$ 参考、单极性范围、特定端点模型、无前端增益和无校准。更稳妥的做法是按数据手册先解释码格式，再使用实测校准系数。

两点线性校准可写为

$$
x=x_0+(D-D_0)\frac{x_1-x_0}{D_1-D_0},
$$

其中 $D_0$、$D_1$ 是施加两个已知输入 $x_0$、$x_1$ 时测得的平均码。校准点应覆盖实际工作范围，校准源精度要优于目标系统精度。

## 5. 偏置、增益和多点校准

- 零点校准补偿近似常量偏置；
- 两点校准补偿偏置和线性增益；
- 多点分段或查表可补偿可重复的非线性；
- 温度分段校准可补偿温漂；
- 在线校准需要已知参考状态或冗余测量。

校准系数应带版本、温度、时间、序列号和 CRC。校准值损坏或超出合理范围时，应回退到安全默认值并报告故障。

## 6. 平均和数字滤波

对独立、零均值随机噪声，平均 $M$ 个样值可使标准差理想下降为

$$
\sigma_{avg}=\frac{\sigma}{\sqrt M}.
$$

平均也会降低带宽并增加延迟。工频、PWM 同步纹波和量化极限环是相关干扰，不一定按 $1/\sqrt M$ 下降。应优先同步采样或针对性滤波，而不是无限增加平均次数。

常见数字处理：

- 滑动平均：计算简单，但频响有旁瓣；
- 一阶 IIR：存储少，具有指数响应；
- FIR：可设计线性相位和明确阻带；
- 中值滤波：适合孤立脉冲，不适合替代模拟抗混叠；
- 同步解调：适合已知激励频率的微弱信号。

## 7. 定点和溢出

整数处理应计算最坏中间值位宽。累加 $M$ 个 $N$ 位无符号码至少需要

$$
N_{acc}\ge N+\lceil\log_2M\rceil
$$

位，不含符号和额外裕量。乘法、偏置减法和符号扩展都可能溢出。饱和运算、舍入方式和缩放因子应显式定义。

## 8. DAC 码值生成

目标输出应先限幅到器件允许范围，再按器件传输函数计算码值并夹紧到 $0\sim2^N-1$。不能让满量程请求生成 $2^N$ 后依赖截断。

```c
uint32_t clamp_dac_code(int64_t code, uint32_t max_code)
{
    if (code <= 0) {
        return 0U;
    }
    if ((uint64_t)code >= max_code) {
        return max_code;
    }
    return (uint32_t)code;
}
```

若使用 STM32 HAL，还要检查通道、对齐格式、触发源、输出缓冲和启动返回值。输出电压应以实测参考和校准曲线换算。

## 9. 数据质量监控

运行时可记录：

- 零码和满量程码出现次数；
- 超范围、过压和参考故障状态；
- DMA 溢出、接口 CRC 和帧错误；
- 每个通道的最小值、最大值、均值和方差；
- 采样周期和时间戳抖动；
- 校准系数版本与温度；
- 通道间不合理跳变或断线特征。

原始码应保留一条可诊断路径。只记录滤波后的工程量会让饱和、失码、采样串扰和接口错位难以定位。

## 10. 软件验证

- 用零码、中间码、满量程码测试码格式和符号扩展；
- 用边界值测试限幅与溢出；
- 断开或延迟数据就绪，检查超时恢复；
- 人为制造 DMA 溢出，确认故障计数；
- 用已知校准点测试正向与反向换算；
- 检查滤波器增益、延迟和启动瞬态；
- 比较时间戳与示波器观察到的真实触发时刻。

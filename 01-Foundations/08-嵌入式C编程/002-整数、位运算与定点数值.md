# 整数、位运算与定点数值

MCU 寄存器、计数器、ADC 码和定点控制量都依赖整数。表达式能编译不代表结果符合直觉，操作数会先经历整数提升和通常算术转换，随后才执行运算。宽度、符号和量纲必须一起检查。

## 类型名称不能替代范围分析

`<stdint.h>` 提供了表达意图的类型：

- `uint8_t`、`int16_t`、`uint32_t` 等精确宽度类型只在实现支持相应宽度时定义；
- `uint_least16_t` 表示至少 16 位且最窄的可用类型；
- `uint_fast16_t` 表示实现认为运算较快的至少 16 位类型；
- `size_t` 用于对象大小和数组索引，`uintptr_t` 在实现提供时用于能往返保存对象指针值的无符号整数。

外设格式和通信帧通常需要精确宽度，循环索引和对象大小更适合 `size_t`。算法中间量应按范围选择类型，不要因为输入是 16 位就让乘积也停留在 16 位。

## 整数提升发生在运算之前

```c
uint16_t a = 50000U;
uint16_t b = 2U;
uint32_t product = (uint32_t)a * (uint32_t)b;
```

显式提升表达了“乘法在 32 位无符号范围中完成”。只在赋值端写 `uint32_t` 不能保证前面的运算没有先溢出。目标平台的 `int` 宽度也会影响 `uint8_t`、`uint16_t` 在表达式中的提升结果。

混合有符号与无符号数时，负值可能先转换成很大的无符号值：

```c
int32_t error = -1;
uint32_t limit = 100U;

/* 不要直接写 error < limit；先统一语义和类型。 */
bool in_range = (error >= 0) && ((uint32_t)error < limit);
```

## 溢出、转换和移位

- 无符号整数按模 $2^N$ 运算，可用于有意设计的计数器回绕。
- 有符号整数溢出属于未定义行为，编译器可以据此优化。
- 超出目标有符号类型可表示范围的转换结果可能由实现定义，不能当作可移植饱和运算。
- 左移负数、移位次数为负或不小于类型宽度都存在未定义行为。
- 右移负有符号数的结果依赖实现，不适合作为可移植的算术右移约定。

构造掩码时让字面量的类型和寄存器宽度一致：

```c
#define BIT_U32(n) (UINT32_C(1) << (n))

uint32_t mask = BIT_U32(5);
```

调用者仍要保证 `n < 32`。面向固定字段时，优先使用器件头文件提供的位置和掩码，不要在业务代码重复手写数字。

## 位操作必须服从寄存器语义

对普通 RAM 变量，置位、清位和取字段可以写成：

```c
value |= mask;
value &= ~mask;
field = (value & FIELD_Msk) >> FIELD_Pos;
```

这些表达式对寄存器并不自动安全。`|=` 和 `&=` 都会先读再写；若寄存器包含写 1 清除、只写、读清除或保留位，读改写可能造成副作用。寄存器访问应按 [[004-寄存器访问、volatile与硬件抽象]] 的方法处理。

## 定点数先定义尺度和范围

Q 格式把整数解释为带固定缩放的实数。若 `raw` 采用 Q15，则常见解释为：

$$
x = \frac{raw}{2^{15}}
$$

两个 Q15 数相乘会得到带 30 个小数位的中间结果，回到 Q15 前需要舍入、移位和饱和：

```c
int16_t q15_mul(int16_t a, int16_t b)
{
    int32_t product = (int32_t)a * (int32_t)b;
    int32_t scaled;

    if (product >= 0) {
        scaled = (product + 16384L) / 32768L;
    } else {
        scaled = -((-product + 16384L) / 32768L);
    }

    if (scaled > INT16_MAX) {
        return INT16_MAX;
    }
    if (scaled < INT16_MIN) {
        return INT16_MIN;
    }
    return (int16_t)scaled;
}
```

这段代码采用绝对值方向的四舍五入，并避开了负有符号数右移的实现差异。其他舍入规则也可以成立，但必须把规则、饱和边界和特殊值写入接口契约，并用边界测试覆盖。

## 量纲应进入命名和接口

`uint16_t speed` 无法说明它是每分钟转数、机械角速度还是电角速度。可用类型、结构体或明确命名保留单位：

```c
typedef struct {
    int32_t milliampere;
} current_ma_t;

typedef struct {
    int32_t electrical_milliradian;
} electrical_angle_t;
```

项目不一定需要为每个单位创建类型，但采样、标定、控制和通信边界必须能看出缩放关系。FOC 中还要区分机械角与电角、峰值与有效值、相量基值以及 Clarke/Park 变换采用的归一化约定。

## 数值代码检查清单

- 写出输入、输出和中间量的最小值、最大值与单位。
- 检查每个二元运算发生前的实际类型，而不只看接收变量。
- 对有意回绕、饱和、截断和舍入分别写测试。
- 位移次数在有效范围内，掩码使用无符号且宽度明确的类型。
- 不用强制转换压掉告警，先确认转换保持了预期数学意义。
- 浮点与定点实现用同一组参考向量比较误差、范围和执行时间。

# 嵌入式 C 编程

嵌入式 C 的难点不在语法数量，而在语言规则、编译器、处理器和外设同时参与程序行为。一个表达式在普通应用中只是算出结果，放进固件后还可能触发寄存器读写、与中断竞争，或落在严格的实时期限内。本目录从程序怎样启动讲起，沿着类型、内存、硬件访问、并发和固件架构逐层展开。

## 一条固件代码链路

```mermaid
flowchart LR
    A["C 源文件与头文件"] --> B["预处理、编译与汇编"]
    B --> C["链接脚本组织映像"]
    C --> D["复位处理与运行时初始化"]
    D --> E["main、ISR 与后台任务"]
    E --> F["寄存器、DMA 与外部设备"]
    F --> G["日志、断言、测试与测量"]
    G -->|发现假设不成立| A
```

读代码时要同时回答三类问题：C 语言是否定义了这种行为，编译器和目标平台如何实现它，硬件手册是否允许这次访问。只回答其中一项，通常不足以证明固件正确。

## 学习顺序

### 先建立语言和执行模型

1. [[001-从复位到main：执行环境与构建过程]]：理解独立式环境、构建链路、启动代码、内存段和映像检查。
2. [[002-整数、位运算与定点数值]]：处理整数提升、转换、移位、溢出、量纲和定点缩放。
3. [[003-指针、对象生命周期与内存安全]]：说明指针有效性的来源，以及对齐、别名、生命周期和所有权约束。

### 再连接硬件与并发

4. [[004-寄存器访问、volatile与硬件抽象]]：区分内存映射 I/O、访问语义、读改写风险和抽象层边界。
5. [[005-中断、并发、原子性与内存顺序]]：分析主循环、中断和执行单元之间的数据竞争与时序关系。
6. [[006-超级循环、状态机与事件驱动]]：把阻塞流程改成有期限、可恢复、可测试的控制流。
7. [[007-DMA、缓冲区与外设数据通路]]：管理异步搬运、缓冲区所有权、缓存一致性和过载策略。

### 最后形成工程闭环

8. [[008-错误处理、断言与故障诊断]]：设计错误传播、故障快照、看门狗和复位后的诊断链。
9. [[009-编码规范、静态分析与测试]]：用规则、工具和分层测试持续检查代码假设。
10. [[010-实时控制固件的架构、时序与验证]]：把前述约束落实到采样、计算、PWM 更新和保护链路。

### 工具链基础

11. [[011-交叉编译工具链的组成]]：arch-vendor-os 三元组命名、binutils/libgcc/C 库/multilib 的目录解剖、bare-metal 与 Linux 工具链的差异。
12. [[012-工具链的获取与版本管理]]：Arm 官方/xPack/包管理器/厂商渠道对比、从源码构建（crosstool-NG、Buildroot、Yocto SDK）、版本随工程管理。
13. [[013-GCC与LLVM双工具链]]：Clang 单二进制多目标的设计、Arm Toolchain for Embedded、同一工程配置两套工具链与树莓派实例。

完成本目录后，可用 [[01-Foundations/13-嵌入式C编程测验题|嵌入式 C 编程测验题]] 检查关键概念。

## 本目录解决什么问题

| 问题 | 本目录给出的判断方法 |
|---|---|
| 一个整数表达式会不会溢出或被错误提升 | 写出每一步的类型、范围、量纲和转换 |
| 指针是否能安全解引用 | 检查对象生命周期、边界、对齐、别名和访问权限 |
| `volatile` 是否足够 | 分开检查可观察访问、原子性、顺序和互斥 |
| 寄存器能否用 `|=` 修改 | 查明读写属性、保留位以及 W1C、W0C、读清除等语义 |
| 中断与主循环能否共享数据 | 明确生产者、消费者、可抢占点和一致性协议 |
| DMA 缓冲区何时归 CPU 使用 | 用所有权状态和平台要求的缓存维护、屏障完成交接 |
| 控制循环能否按时完成 | 测量最坏执行时间、抖动和端到端期限，不只看平均耗时 |
| 代码是否适合交付 | 让编译告警、静态分析、测试、测量和评审共同提供证据 |

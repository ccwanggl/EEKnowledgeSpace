# 指针、对象生命周期与内存安全

指针只保存一个地址表示。地址非零、落在 RAM 范围内，仍不足以证明可以解引用。一次合法访问还需要对象确实存在、类型兼容、对齐正确、没有越界，并符合读写权限和并发约定。

## 指针有效性来自对象

检查一次解引用时，可以沿着下面的顺序判断：

1. 指针来自哪个对象或平台定义的地址？
2. 对象的生命周期是否仍在继续？
3. 当前指针是否位于对象或尾后位置允许的范围内？
4. 访问类型是否满足有效类型与别名规则？
5. 地址是否满足目标类型的对齐要求？
6. 对象是否允许当前方向的读写？
7. 是否存在中断、DMA 或其他执行单元同时修改它？

返回局部对象地址会在函数返回后留下悬空指针；把任意字节地址转成 `uint32_t *` 还可能违反对齐和类型规则。强制转换只改变编译器看见的类型，不会创建对象，也不会修复生命周期。

## 数组退化不会携带长度

函数参数中的 `uint8_t data[]` 通常按指针处理，函数无法从指针恢复数组元素个数。接口应显式传递长度，并把容量与实际长度分开：

```c
bool frame_encode(uint8_t *dst,
                  size_t capacity,
                  size_t *written,
                  const uint8_t *payload,
                  size_t payload_len);
```

这个接口仍需规定空指针是否允许、失败时 `written` 的值、输入输出能否重叠，以及最大帧长。函数签名只表达了一部分契约。

## 存储期与生命周期

| 存储期 | 常见对象 | 主要风险 |
|---|---|---|
| 自动 | 普通局部变量 | 返回地址后失效、栈占用过大、未初始化读取 |
| 静态 | 全局对象、`static` 对象 | 隐式共享、初始化依赖、长期占用 RAM |
| 动态 | `malloc` 等获得的对象 | 分配失败、碎片、泄漏、释放后使用、时延不确定 |
| 线程 | 线程局部对象，取决于实现支持 | RTOS 和工具链支持、每任务内存成本 |

资源受限或硬实时系统常限制运行期动态分配，但这不是 C 语言的统一禁令。若项目允许动态内存，应明确分配阶段、失败处理、最长执行时间、线程安全和碎片控制。固定块内存池也需要同样的所有权规则。

## `const` 表达访问意图

```c
void filter_run(filter_t *state,
                const int16_t *input,
                int16_t *output,
                size_t count);
```

`const int16_t *input` 表示函数不能通过该指针修改输入对象，不保证对象位于只读存储器，也不保证其他代码不会修改它。把接口中不需要修改的对象标成 `const`，能减少误写并让调用关系更清楚。

顶层 `const` 和指向对象的 `const` 含义不同：

```c
const uint8_t *p;       /* 不能通过 p 修改所指字节 */
uint8_t * const q = buf; /* q 本身不能改指向 */
```

## 对齐、填充与序列化

结构体成员之间可能有填充，结构体末尾也可能为数组对齐保留空间。不能把内存中的结构体直接当作稳定的通信帧、文件格式或 Flash 配置格式。编译器、ABI、端序和版本变化都可能改变布局。

```c
uint16_t load_u16_le(const uint8_t src[2])
{
    return (uint16_t)src[0]
         | (uint16_t)((uint16_t)src[1] << 8);
}
```

逐字段编码能显式控制端序和范围，也避开未对齐解引用。`packed` 只改变特定编译器下的布局请求，可能生成低效访问，某些处理器还会因未对齐访问触发故障。若必须使用编译器扩展，应限制在边界层并配合静态断言、目标平台测试和字节级用例。

## 别名与类型重解释

通过不兼容类型的左值访问同一存储，可能违反 C 的别名与有效类型规则。查看浮点数位模式时，优先用 `memcpy` 或实现明确支持的位转换方式：

```c
#include <stdint.h>
#include <string.h>

uint32_t float_bits(float value)
{
    uint32_t bits;
    _Static_assert(sizeof bits == sizeof value, "unexpected float size");
    memcpy(&bits, &value, sizeof bits);
    return bits;
}
```

`_Static_assert` 从 C11 开始可用，较早语言版本可使用工具链提供的静态断言。还应确认实现的浮点格式和端序，不能仅凭大小相同推断 IEEE 754 表示。

## 所有权要能从接口看出来

嵌入式项目中的所有权不一定意味着动态内存，更多时候表示“当前谁可以读写这块缓冲区”。一个 DMA 发送缓冲区可能依次由应用、驱动和外设拥有。所有权交接前修改内容，会产生难以复现的数据损坏。

可以用以下信息表达约定：

- 谁创建并保持对象有效；
- 谁能修改，谁只能借用只读视图；
- 回调返回后指针是否仍有效；
- 异步操作在什么事件后完成；
- 超时、取消或复位时由谁回收状态。

## 检查清单

- 每个指针参数都有长度、可空性、方向和生命周期约定。
- 不返回局部对象地址，不保存短生命周期缓冲区的借用指针。
- 通信、存储和寄存器格式不依赖普通结构体的隐式布局。
- 强制转换前能解释对象、对齐、别名和访问权限为何成立。
- DMA、ISR 和回调共享的缓冲区有明确所有权交接。
- 大型局部数组和递归经过栈预算分析。

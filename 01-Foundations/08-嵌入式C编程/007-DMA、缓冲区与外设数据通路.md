# DMA、缓冲区与外设数据通路

DMA 减少了 CPU 搬运数据的工作，却增加了一个会异步访问内存的执行者。缓冲区何时可写、何时可读、完成事件代表什么，以及缓存中的数据是否已经与内存一致，都需要明确协议。

## 用所有权描述数据流

```mermaid
flowchart LR
    A["应用填充"] --> B["提交给驱动"]
    B --> C["DMA/外设拥有"]
    C -->|完成或错误事件| D["驱动确认"]
    D --> E["归还应用"]
    E --> A
```

应用提交发送缓冲区后，不应在完成前修改内容；接收缓冲区交给 DMA 后，CPU 不应把半更新的数据当成完整帧。超时和取消还要说明 DMA 是否真的停止、回调是否可能稍后到达，以及缓冲区何时重新归还。

## 选择适合数据节奏的缓冲方式

| 方式 | 适合场景 | 需要处理的边界 |
|---|---|---|
| 单缓冲 | 低速、处理能在下一批数据前完成 | 处理期间可能丢新数据 |
| 双缓冲 | 连续等长采样或发送 | 两块缓冲区的交接和超期处理 |
| 环形 DMA | 连续字节流、未知帧边界 | 写指针快照、回绕和覆盖 |
| 软件环形队列 | ISR 与主循环之间传递小元素 | 单/多生产者模型、满与空 |
| 缓冲池 | 多个异步请求、不同生命周期 | 块耗尽、归还和泄漏检查 |

双缓冲能让 DMA 填充一块时 CPU 处理另一块，但 CPU 的最坏处理时间仍必须短于缓冲区被再次需要的时间。缓冲只吸收有限突发，不会提高长期平均吞吐能力。

## 环形缓冲区先定义并发模型

下面的接口能区分“队列为空”和“成功读到字节 0”：

```c
bool byte_ring_try_push(byte_ring_t *ring, uint8_t value);
bool byte_ring_try_pop(byte_ring_t *ring, uint8_t *value);
size_t byte_ring_count(const byte_ring_t *ring);
```

实现前还要规定：

- 是单生产者单消费者，还是允许多个生产者；
- 生产者和消费者分别在哪个执行上下文；
- 队列满时拒绝新数据、覆盖旧数据还是触发故障；
- 索引读写在目标平台是否原子；
- 发布数据与更新索引之间需要什么顺序保证；
- `count` 是否只是诊断快照，能否用于后续原子决策。

`volatile` 索引不能建立发布与消费顺序。可以使用经过平台验证的原子操作、很短的临界区，或符合单生产者单消费者约束的专用实现。通用多生产者无锁队列复杂度高，通常不适合作为默认方案。

## DMA 与缓存一致性

在带数据缓存的 MCU 上，CPU 可能只修改了缓存行，DMA 仍从主存读到旧数据；DMA 写入主存后，CPU 也可能继续读取缓存中的旧副本。常见交接动作包括清理缓存、失效缓存、内存屏障和对齐缓存行，准确顺序取决于缓存策略、DMA 方向和平台实现。

需要验证：

- 缓冲区位于 DMA 可访问的存储区；
- 地址和长度满足 DMA 与缓存行要求；
- 缓存维护覆盖完整缓存行，不误伤共享的邻接对象；
- 提交前和完成后的平台屏障位置正确；
- 描述符与数据缓冲区分别执行所需维护；
- MPU 或非缓存区设置与链接脚本一致。

具体操作见 [[04-Microcontrollers/06-中断与DMA深入/003-Cache一致性|Cache 一致性]]，不能用 `volatile` 缓冲区代替缓存维护。

## 流式解析要能重新同步

协议解析器应逐步消费输入，并显式记录当前状态、已收长度和截止时间。面对错误输入时至少考虑：

- 帧头重叠和部分匹配，例如 `AA AA 55`；
- 长度字段超过本地容量；
- 帧中断后的接收超时；
- 校验失败后的重新同步位置；
- 队列积压和持续噪声；
- 回调重入或解析期间修改同一缓冲区。

解析层只验证边界并产出完整消息，业务回调可由上层调度。对外部可控输入，主机端模糊测试和消毒器能更快发现越界、整数溢出和状态遗漏。

## 采样数据要带上时间含义

控制系统中的样本除了数值，还需要知道它对应哪个采样时刻、通道序列和标定状态。ADC 扫描、DMA 完成中断与控制计算之间可能有固定延迟，双缓冲还会增加一批数据的处理延后。接口可以携带序号和时间戳，检测丢批、重复和过期样本。

FOC 电流环通常依赖 PWM 触发、ADC 采样、DMA 或中断、坐标变换和 PWM 更新形成确定链路。各环节的期限在 [[010-实时控制固件的架构、时序与验证]] 统一分析。

## 检查清单

- 缓冲区在应用、驱动和 DMA 之间有明确所有权状态。
- 完成、错误、超时和取消都定义缓冲区何时归还。
- 队列 API 能区分有效零值与失败，满载策略可以观测。
- 环形缓冲区实现与生产者/消费者模型严格匹配。
- 带缓存平台执行正确的缓存维护、对齐与屏障。
- 解析器限制长度、支持超时和重新同步，并对坏输入测试。
- 连续数据流验证的是最坏处理能力，不只验证短时间不丢包。
